# P3b — «Дубли и запись», desktop

Ветка `feat/p3b-takes` от `feat/p3a-thought-desktop`. Только desktop (оболочка ≥ 1200 px, как в P3a); ниже — прежний вид без изменений. Логика, API и данные не менялись, токены модели не тратились.

## Что сделано

### Вкладка «Дубли» (эталон 01, takes-path из vocalv0 @ e27caf4)
- Зигзаг полароидов (слева–справа) с пунктирной S-кривой между соседними; органичные смещения и лёгкий наклон; после шести слотов путь продолжается кругом.
- Порядок «от последнего» (по умолчанию) / «от первого»; «призрак» «Следующий дубль» стоит перед самым новым (первый при «от последнего», последний при «от первого») и открывает запись той же дорогой, что «+ Новый дубль».
- Три действия на дубле при наведении/фокусе: **Слушать** (мини-плеер с прогрессом, один дубль за раз), **Читать** (диалог с расшифровкой, только чтение), **Видео** (диалог с плеером; только у готового видео, воспроизводимого в браузере). Слушать — только при готовом воспроизводимом файле.
- Меню «…» на дубле (выпадающее `PopoverMenu`, P3a): «Сделать итоговым» / «Снять итоговый» (тот же PATCH `finalTakeId`, как раньше), «Удалить дубль» (красное → `ConfirmAlert`, тот же `DELETE /api/takes/:id`, безопасное «Оставить» в фокусе).
- Штамп «итоговый» на итоговом дубле; квадрат полароида — реальный кадр видео (`<video preload="metadata">`), иначе главная мысль (из сохранённого разбора или начало текстового дубля), иначе значок «Аудио/Текст».
- Подпись «Дубль N · Аудио/Видео/Текст»; заметка «Что менял» перенесена в диалог «Читать» (сохранение по уходу из поля, тот же PATCH).

### Экран записи (эталон 02)
- Слева ~70 % (измерено 678 / 290 px): телесуфлёр Literata 28/1.5 с кнопкой «Скрыть»; справа компактная колонка ~300 px: индикатор микрофона (уровень), «Начать запись» на всю ширину, состояния ниже.
- Запись стартует только после «Начать запись»: единственный вызов `startRecording()` — обработчик этой кнопки (тест), в браузере до нажатия состояния записи нет. Диалога ИИ нет. «← К пути» — тот же выход с подтверждением отмены.
- Состояния — существующей логикой `RecordingView`: готов, запрос микрофона, идёт запись (таймер, уровень), предпросмотр, сохранение, сохранено, нет доступа к микрофону (сообщение с инструкцией), подтверждение отмены.

## Данные: что есть, чего нет (честно)

| Элемент | Источник | Состояние в продукте |
| --- | --- | --- |
| Облачко ИИ | сохранённое сравнение `GET /api/reels/:id/compare`, `semantic.thoughtPreserved` | **Новые смысловые сравнения не создаются** (`POST …/compare` с `runAi` → 410). Облачко есть только у дублей со старым сохранённым сравнением; у новых мыслей его нет — не рисуется |
| Вывод под карточкой | то же, `semantic.notes` | как выше |
| Стикеры «Что улучшить» | сохранённый разбор `GET /api/takes/:id/review`, `result.missing` | **Новые разборы не создаются** (панель разборов — архив). Есть только у старых разборов; иначе стикера нет |
| Главная мысль в квадрате | сохранённый разбор `result.authorThought` / текст текстового дубля | как выше; иначе значок |
| Длительность на рамке | — | в `TakeDto` нет длительности; вместо неё тип дубля. Нужен бэкенд (длительность файла) |
| Превью камеры | — | запись в браузере только аудио (`getUserMedia({audio})`), видео-записи нет → превью камеры не показываю; на его месте индикатор микрофона |
| Переключатели микрофона/камеры | — | в продукте нет выбора устройства; не добавлял, чтобы не менять логику записи |
| «Расшифровка», «Проверка», «Не расслышали» как экраны записи | — | после сохранения расшифровку ведёт существующий `StudioJobWatch` на вкладке дублей; отдельных состояний в `RecordingView` нет |

Скриншоты облачков/стикеров сделаны на **подсаженных в локальную тестовую БД** сохранённых сравнениях и разборах (такие записи в продукте существуют только исторически); дубли и файлы созданы через настоящие эндпоинты (`/api/uploads`, `/api/reels/:id/takes`).

## Что перенесено / отличается от прототипа
- Список дублей мобильного вида, ленты и `AutoTakeCompare` («Сохранённые сравнения») на desktop заменены путём; несопоставленные пары сравнений (не «соседний более новый дубль») на desktop не показываются — на мобильном они остались.
- Загрузка видео (`TakeUploadDropzone`) и форма «исходный текст» (когда дублей нет) сохранены: свёрнутый блок «Загрузить видео вместо записи» и та же форма под путём.
- «Править расшифровку» открывает существующий `TranscriptEditor` внутри диалога «Читать» (в прототипе чтение «только», но в продукте правка есть — не теряю).
- «сравнивает ИИ» из заголовка прототипа не пишу: сравнение само не запускается.
- Видеодиалог — нативный `<video controls>`, а не имитация.
