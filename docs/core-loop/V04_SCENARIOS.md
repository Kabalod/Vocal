## Хранение, union, уникальность, выбор среза

1. **Слабое наблюдение в event, ревизии нет.** `apply_update` + `add_observation` + `confidence = 0.4`. Принятый event в `resultJson`. `system_weight` не растёт. Новой `ProfileRevision` нет. Исторические ревизии не тронуты.
2. **Историческая ревизия неизменна.** После нового наблюдения (даже с новой ревизией среза) `payloadJson` прежних `ProfileRevision` тот же.
3. **no_change и thought_specific без фиктивных полей.** Ответ с `category`/`value` при этих `kind` — отказ. Валидный `no_change` (`reasonCode`) и `thought_specific` (`reasonCode`, опционально `auditUserMessageId`) не пишут event основания и не создают ревизию.
4. **Один id: сначала support, затем oppose того же слота.** Второй кандидат — отказ. Вес прежний. Нового event нет.
5. **Повтор хода.** Тот же idempotency / тот же `AiCall`. Второго event нет. Срез и ревизии те же.
6. **Сбой между ответом модели и записью.** Транзакция не проходит. Нет `event` в `done` AiCall, нет смены `currentRevisionId`, processing не выглядит успешно принятым. Повтор хода либо дописывает атомарно всё, либо снова чисто отказывает.
7. **Два конкурентных хода.** Сериализация по профилю. Второй после ожидания заново читает events, источники и пороги. Оба не пишут один id в один слот. Пороги считаются последовательно.
8. **Новый слот обгоняет по весу.** Два допущенных слота одной категории; вес нового строго больше. Отображаемое `value` меняется. Ровно одна новая `ProfileRevision`.
9. **Равные веса.** Новый слот допущен с тем же `system_weight`, что текущий отображаемый. Текущее `value` остаётся. Ревизии нет.
10. **Снятие текущего слота.** `weaken` до `weight <= 1`. Если есть другой допущенный слот — он становится отображаемым (макс. вес, при равенстве лексикографический `value`). Если допущенных нет — категория исчезает. Ревизия только если срез изменился.
11. **Старые AiCall не replay.** `heal` / пересчёт веса игнорирует `profile_dialogue` без `schemaVersion = "v04-event-1"`. Срез из них не появляется.
12. **Старый pending не публикуется.** На BASE есть `pending.readyToConfirm` без `portrait.completed`. Автопубликации нет. Действующий снимок — только уже опубликованный портрет или пусто.

## Структура apply_update (как раньше, в терминах union)

13. **Confidence вне [0, 1].** Отказ, event нет.
14. **Неизвестная категория** в `apply_update`. Отказ (enum), не NLP.
15. **Дубль id в одном кандидате.** Отказ.
16. **Ассистент / чужой thread / диалог мысли** в evidence. Отказ.
17. **Несовместимый переход.** `replace_explicit` на производной или `behavioral_observation` на прямой. Отказ.
18. **Прямая общая цель.** Один валидный `apply_update` + `replace_explicit`. Срез меняется. Одна новая ревизия, без confirm.
19. **Повтор того же прямого value.** Event допустим, если id новый для этой пары `(category, value)`; срез тот же — ревизии нет. Тот же id — отказ (сценарий 4).
20. **Одно основание ниже порога публикации.** `confidence >= 0.5`, вес 1. Event есть, среза нет, ревизии нет.
21. **Три независимых id, вес 3.** Слот допущен, срез появляется, одна ревизия.
22. **Strengthen / weaken без смены среза.** Event есть, ревизии нет.
