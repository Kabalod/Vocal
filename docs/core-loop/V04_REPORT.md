## Аудит текущей реализации

На BASE портрет — отдельный диалог профиля с чеклистом из восьми полей (`whyRecord`, `blogGoal`, `audience`, `lifeNow`, `experience`, `topics`, `speakingStyle`, `boundaries`). Модель возвращает `operations` / `patch`, `complete`, `kind` (`clarify` | `ready`). Сервер пишет промежуточные `ProfileRevision` на каждый удачный ход и публикует действующий портрет только через `confirmProfilePortrait`.

Публикация: `stored.portrait.completed === true` и `pending = null`. До confirm runtime (`runtimePortraitFields`, `runtimePortraitRevisionId`) отдаёт пустые поля. Диалог мысли и сборка `reel-context` видят портрет только после confirm.

Amend держит прежние `fields` и показывает черновик `pending.draftFields` с `readyToConfirm`. Кнопка «Подтвердить портрет» в `ProfileConversation`. Промпт явно: `complete=true` — черновик к подтверждению, не действующий портрет.

Минимум готовности intake: цель (`whyRecord` или `blogGoal`) и аудитория или темы. Amend готов при `hasChange` или `noChange`.

Фильтров «устойчивое vs эпизод мысли», запрета похвалы и диагнозов, запрета деталей разговора в полях нет. Модель может записать в `lifeNow` / `experience` пересказ ответа как есть.

`usage` (`in_text` | `understanding`) — ручной регулятор «можно в текст». `saveProfile` (PUT `/api/profile`) принимает произвольные поля. Чеклист и usage — ручное управление предпочтениями.

В промпт диалога мысли (`dialogue.ts`) и в `ai/script.ts` / `ai/review.ts` попадают `publicForScript` и `understandingOnly`. Портрет тем самым может стать материалом сценария, если `usage=in_text`.

Без confirm основной цикл уже работает: skip и пустые runtime-поля не блокируют мысль. Это совпадает с целевым «без портрета цикл жив», но расходится с целевой авторевизией.

Диалог профиля не использует `turnKey` / exec-lease V03. Inflight — `withAiInflight` по ключу профиля. Это не блокер контракта содержания; идемпотентность профиля — отдельный риск, не менять схему в V04-00.

`healStoredPortrait` переигрывает прошлые `AiCall` профиля, если покрытых полей нет. Риск повторно втянуть сырые смыслы после смены фильтров — учесть при продукте.

## Расхождения `confirmProfilePortrait` с целевым V04

| Сейчас | Цель V04 |
|---|---|
| Публикация только после `action=confirm` и `pending.readyToConfirm` | Новая ревизия из прошлого портрета и новых ответов, без confirm |
| Amend не меняет действующие `fields` до кнопки | Действующая ревизия обновляется после фильтров на ходе диалога |
| Intake пишет поля, но `portrait.completed` false до confirm | Есть ревизия — её можно смотреть; нет отдельного «черновик не действует» |
| Runtime пустой, пока нет confirm | Runtime = последняя отфильтрованная ревизия; пусто только если ревизии нет |
| UI «Подтвердить портрет», `awaitingConfirm`, `draftPortrait` | Просмотр портрета + продолжить разговор |
| Промпт: `kind=ready` = показать черновик к подтверждению | Промпт: вопрос ведёт к ясной общей мысли; готовность = серверные фильтры, не кнопка |
| `saveProfile` и `usage` как ручные предпочтения | Ручного редактирования весов и полей нет |
| Нет отсечения деталей мысли / похвалы / диагнозов | Обязательные серверные фильтры |
| `publicForScript` кормит сценарий и разбор | Портрет не источник событий и фактов сценария |
| Чеклист покрытия полей | Вопросы проясняют устойчивые сведения и способ выражения |
| Повторный confirm без pending — no-op, если уже completed | Повтор хода без смысла не создаёт пустую ревизию; confirm API нет |

Функция `confirmProfilePortrait` (строки ~453–490 `profile-dialogue.ts`) — единственная публикация `buildPortrait(fields, true)` с очисткой `pending`. Целевой путь эту функцию удаляет или оставляет мёртвой совместимостью без вызова из API/UI.

## План небольших продуктовых коммитов

Не начинать, пока пользователь не даст этап после V04-00. Один смысл — один коммит. Не смешивать с V05. Не трогать Prisma.

1. **Фильтры содержания.** Сервер отбрасывает эпизоды мысли, похвалу, диагнозы, ярлыки; оставляет устойчивое и способ выражения. Тесты на патч. Промпт профиля без «для сценариев» и без confirm.
2. **Авторевизия.** Ход диалога после фильтров пишет действующую ревизию. `readyToConfirm` не публикует. Runtime читает последнюю ревизию.
3. **Снять confirm.** Убрать API `action=confirm`, кнопку, `awaitingConfirm` / черновик-гейт. Обновить тесты `profile-dialogue`, `p10-p12`, `r2`, `mvp-release`, `p17-e2e`.
4. **Закрыть ручные регуляторы.** Не вызывать `saveProfile` из UI профиля; usage не как вес; не добавлять слайдеры.
5. **Приоритет мысли.** В промпте диалога мысли портрет — предположение для формулировки вопроса, не факт. Не писать поля портрета в `thoughtUpdate.fact`. Пустой портрет: V03 без изменения действий.
6. **Не источник сценария.** Не класть портрет в `publicForScript` как события ролика. Стык `reel-context` / prompt: понимание отдельно; генерация сценария не расширяется (V05).

После каждого продуктового коммита: `npm run test:v03` если задет диалог мысли; тесты профиля этапа; typecheck. Полный `test:postgres` — перед внешней приёмкой V04, не в V04-00.
