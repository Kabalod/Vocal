## Аудит текущей реализации

На BASE портрет — чеклист из восьми полей и свободный `operations` / `patch`. Нет enum прямых/производных категорий, нет кандидата с `scope` / `evidenceType` / `confidence` / `operation`, нет журнала слотов и целочисленных порогов. Каждый ход пишет `ProfileRevision`; публикация — только `confirmProfilePortrait`.

Runtime до confirm пустой. `usage` и `saveProfile` — ручные регуляторы. Промпт мысли и `ai/script.ts` могут получить `publicForScript`. Сервер сливает текст patch и **не** проверяет enum/пороги; он также **не** должен в целевом V04 «понимать» похвалу в строке — этого механизма на BASE нет и в контракте не будет.

## Граница, которой на BASE нет

Целевой V04: модель классифицирует; сервер проверяет enum, источники, совместимость переходов, `confidence ∈ [0, 1]`, уникальность id, `system_weight = support_n - oppose_n`, `PUBLISH_THRESHOLD = 3`, `REMOVE_THRESHOLD = 1`. Запрет настроения и диагноза = отсутствие таких ключей в enum, не NLP по `value`.

## Расхождения с целевым V04

| Сейчас | Цель V04 |
|---|---|
| Свободные поля + patch | Строгий кандидат и закрытые enum |
| Нет порогов | Вес и гистерезис 3 / 1; слабое `confidence < 0.5` вес не двигает |
| Ревизия на каждый ход + confirm | Ревизия только при смене отображаемого среза; confirm нет |
| Нет проверки id | User + владелец + profile thread; дубликаты — отказ |
| Сервер пишет любой text | Сервер не толкует `value`; прямое сведение сравнивает как нормализованную строку |
| `saveProfile` / `usage` | Слайдеров и ручных весов нет |
| `publicForScript` в сценарий | Портрет не источник событий сценария |
