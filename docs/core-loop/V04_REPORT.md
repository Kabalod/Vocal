## Аудит текущей реализации

На BASE портрет — отдельный диалог профиля с чеклистом из восьми полей (`whyRecord`, `blogGoal`, `audience`, `lifeNow`, `experience`, `topics`, `speakingStyle`, `boundaries`). Модель возвращает `operations` / `patch`, `complete`, `kind` (`clarify` | `ready`). Сервера нет разделения прямых утверждений и производных наблюдений. Нет кандидата с `scope`, `evidenceType`, `evidenceMessageIds`, `confidence`, `operation`. Каждый удачный ход пишет `ProfileRevision`; действующий портрет публикует только `confirmProfilePortrait`.

Публикация: `stored.portrait.completed === true` и `pending = null`. До confirm runtime (`runtimePortraitFields`, `runtimePortraitRevisionId`) отдаёт пустые поля. Диалог мысли и `reel-context` видят портрет только после confirm.

Amend держит прежние `fields` и показывает черновик `pending.draftFields` с `readyToConfirm`. Кнопка «Подтвердить портрет» в `ProfileConversation`. Промпт: `complete=true` — черновик к подтверждению.

Минимум готовности intake: цель и аудитория или темы. Amend готов при `hasChange` или `noChange`. Это плоское «есть текст в поле», не порог веса наблюдений.

Фильтров «прямое vs производное», «устойчивое vs настроение / эпизод мысли», запрета похвалы и диагнозов нет. Модель может записать пересказ ответа в `lifeNow` / `experience` / `speakingStyle` с одного хода.

`usage` (`in_text` | `understanding`) — ручной регулятор. `saveProfile` принимает произвольные поля. Веса системы нет; пользовательские слайдеры тоже нет, но usage и PUT — ручное управление.

В промпт диалога мысли и в `ai/script.ts` / `ai/review.ts` попадают `publicForScript` и `understandingOnly`. Портрет может стать материалом сценария при `usage=in_text`.

Без confirm основной цикл уже работает. Диалог профиля без `turnKey` / exec-lease; inflight — `withAiInflight`. `healStoredPortrait` переигрывает прошлые `AiCall` — риск втянуть сырые смыслы после смены контракта.

## Расхождения с целевым V04

| Сейчас | Цель V04 |
|---|---|
| Плоские поля + patch | Кандидат: `category`, `value`, `scope`, `evidenceType`, `evidenceMessageIds`, `confidence`, `operation` |
| Любой текст поля равен характеристике | Прямое общее утверждение может обновить с одного ответа; производное — только накоплением |
| Нет журнала оснований | Наблюдения с источником, уверенностью, согласованностью, системным весом |
| Каждая запись хода = `ProfileRevision` | Новая ревизия только при значимом изменении действующего портрета |
| Confirm публикует | Модель предлагает, сервер проверяет структуру и пороги; пользователь не подтверждает |
| Нет проверки id оснований | Только существующие сообщения пользователя profile dialogue; ассистент и диалог мысли запрещены |
| Нет `scope` | `thought_specific` не входит в глобальный портрет |
| Сервер сливает patch как текст | Сервер не толкует смысл; проверяет схему, источники, пороги, переходы |
| `saveProfile` / `usage` | Ручных весов и слайдеров нет |
| `publicForScript` в сценарий | Портрет не источник событий и фактов сценария |

`confirmProfilePortrait` — единственная публикация `buildPortrait(fields, true)`. Целевой путь функцию из API/UI убирает.

## План небольших продуктовых коммитов

Не начинать, пока пользователь не даст этап после V04-00. Один смысл — один коммит. Не смешивать с V05. Не трогать Prisma.

1. **Схема кандидата.** Тип обновления и серверные проверки источников, `scope=global`, категории, запрещённых полей, запрета ссылок на ассистента и диалог мысли. Тесты структуры. Без смены UX confirm.
2. **Прямое vs производное.** Один явный общий ответ обновляет прямую категорию. Одно случайное наблюдение — `add_observation` / `no_change`, действующий портрет без изменений. Похвала, диагноз, настроение, деталь мысли не публикуются.
3. **Веса и история.** `strengthen` / `weaken`; противоречие не затирает основания. Вес считает система. Слайдеров нет.
4. **Ревизия по значимости.** Новая `ProfileRevision` только при значимом изменении действующего среза. Повтор и слабое наблюдение ревизию не создают. Confirm не нужен.
5. **Снять confirm.** Убрать API `action=confirm`, кнопку, `awaitingConfirm`. Обновить тесты профиля.
6. **Стык с циклом.** Промпт мысли: портрет как предположение. Не писать портрет в `thoughtUpdate.fact`. Не класть портрет в `publicForScript` как события. V05 не начинать.

После каждого продуктового коммита: тесты профиля этапа; `test:v03` если задет диалог мысли; typecheck. Полный `test:postgres` — перед внешней приёмкой V04, не в V04-00.
