# V00 — решения аудита (ADR)

Приоритет: `план разработки/Vocal_Core_Loop_Cursor/PLAN.md`. Ниже — факты кода на `4ac28630692860a3092cf6c4cbc05ed791eb549d` и решения, которые V01+ не должны размывать.

## A. Состояние мысли

**Есть:** `Reel.status` строка, default `draft`. UI и API знают `in_progress` и `completed`. В фильтрах архива `in_progress` включает алиасы `active`, `ready_to_record` (`src/lib/reels.ts`).

**Нет:** таблицы/модели `ThoughtState`, отдельного reducer, явной машины переходов кроме патчей `updateReel`.

**Решение плана:** ввести состояние мысли на V03, не эмулировать его только статусом карточки без контракта. V00 схему не меняет.

## B. Рабочий дубль vs итоговый

**Есть:** `selectedTakeId`, `finalTakeId`. Завершение смотрит на `finalTakeId` / `finalScriptId` (gate в грязном дереве; на HEAD — логика в `reels.ts` + backfill в `thought-completion.ts`).

**Нет:** `workingTakeId`. Handler `suggest_take` в `src/` отсутствует.

**Решение плана:** V04 вводит рабочий дубль и предложение дубля. Не подменять `finalTakeId` рабочим выбором.

## C. Контекст диалога: `take: 2`

В `buildThoughtMaterialContext` (`dialogue.ts`):

```ts
takes: { orderBy: { number: "asc" }, take: 2 }
```

Это **лимит Prisma (два ряда)**, не «второй дубль как концепция». Затем берётся take с `id === selectedTakeId` или `takes[0]`.

Третий и далее дубли **не попадают в выборку**. Если выбранный дубль не среди первых двух по `number`, материал диалога может быть чужим или пустым.

**Решение плана:** V01/V04 читать рабочий/выбранный дубль по id, не обрезать список до двух.

## D. `withAiInflight`

Ключи на HEAD:

- диалог мысли: `dialogue:${reelId}:${key}`
- диалог профиля: `profile-dialogue:${key}`

Поведение: если ключ уже в `Map`, **вернуть тот же Promise**. Класс `AiInflightError` (409) **не используется** этой функцией.

Это не процессный lock и не отказ второму клиенту. Два разных ключа (разный `key` сообщения) идут параллельно.

**Решение плана:** V01 зафиксировать контракт (дедуп vs 409) явно в коде этапа; не считать текущий Map заменой `operationId`.

Дневной бюджет (`assertDailyTokenBudget`) — сумма токенов `AiCall` за сутки, без `ownerUserId` в агрегате. После Auth это общий счётчик процесса, не per-user.

**Решение плана:** V02 — сценарий в том же ходе диалога, без второго чата. Не плодить UI выбора.
