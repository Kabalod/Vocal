# V00 — зависимости, без которых V01 нельзя начинать

V00 — аудит. Он **не** снимает блокеры ниже.

## Блокеры V01 (очередь)

1. **Приёмка документов V00** пользователем (агент «Создание приложение»). Пока нет — код ядра не менять.
2. **Назначенный BASE_SHA.** Кандидат: `4ac28630692860a3092cf6c4cbc05ed791eb549d`. Назначить можно только если этот снимок принят как база приложения **или** пользователь явно указывает другой чистый SHA.
3. **Приёмка Auth** как продукта. Код на кандидате есть (`ownerUserId`, session, `/login` `/signup`). Самоподтверждение, изоляция A/B и «почта в UI» без решения пользователя — не база.
4. **Приёмка лендинга L00–L07** — отдельный цикл. Не блокер логики диалога, но **блокер чистоты дерева**: смешивать V01 с незакоммиченным лендингом/Auth-polish нельзя.
5. **Грязное дерево.** `dialogue-reply`, `thought-opening`, gate завершения и прочий uncommitted код **не** база. Либо принять отдельным коммитом до V01, либо не включать в BASE.

## Не блокеры V01 (решать на своих этапах)

- Нет `ThoughtState` / `workingTakeId` / `suggest_take` — это работа V03–V04, не причина откладывать принятый V01 после BASE.
- Confirm профиля — I05.
- I01 память, scoring-v1, craft library — другой цикл.
- FAQ лендинга, настоящее видео автора — лендинг.
- MCP / Studio / EPERM Prisma при живом Next — среда, не продукт.
- Красные тесты профиля как техдолг — не чинить «заодно» в V00.

## Совместимость стека

Оставить: Next 15, Prisma 6, Postgres приложения (pooler), Groq, Zod, `AiCall`, существующие Reel/Take/Dialogue/Script.

SQLite — тестовый контур, не перенос данных в продукт.

## Документы, которые другие этапы правят (не V00 кодом)

- I00 FILE_MAP — устарел по SQLite/`local`; обновить после назначенного BASE (можно тем же коммитом, что назначение, не этим аудитом если SHA не принят).
- `AGENTS.md` пункт «текущий цикл» — после приёмки V00 сменить на V01 этого плана.
- `PERSONAL_MVP` / confirm — I05.

## Расход

V00: ноль модели, ноль миграций.
