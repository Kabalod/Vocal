Источник правил: `план разработки/Vocal_Core_Loop_Cursor/PLAN.md`. Этот файл — продуктовый и процессный контракт будущих этапов V01–V07.

## Путь

Исходная мысль → один уточняющий вопрос → предложение следующего дубля → разбор дубля → следующий вопрос или `content_sufficient`.

Развёрнуто:

1. Автор формулирует исходную мысль (текст, голос в чате или материал дубля).
2. Агент задаёт **один** уточняющий вопрос по существенному пробелу.
3. Когда материала достаточно для записи, агент предлагает **следующий дубль** с понятной задачей (`suggest_take`).
4. После обработки нового дубля агент разбирает **то, что сказано в записи**, не ответ из чата.
5. Дальше снова один вопрос **или** сообщение о достаточности результата (`content_sufficient`).
6. Когда мысль донесена, агент не требует новых дублей без причины.
7. **Итоговый дубль выбирает пользователь.**

Камера не включается сама. Голосовое сообщение в диалоге и запись дубля — разные действия. Автор может продолжить разговор или перейти к записи сам.

## Действия агента

Внутренние действия, не новые пользовательские статусы мысли (`draft` / `in_progress` / `completed` остаются):

| Действие | Смысл | Обязательные поля (V03+) |
|---|---|---|
| `ask_question` | Один смысловой вопрос | вопрос; id пробела или причина уточнения; объяснение для аудита, почему ответ ещё не известен |
| `suggest_take` | Предложить записать следующий дубль | основная мысль из материала автора; задача записи; ссылки на основания |
| `content_sufficient` | Существенных пробелов нет | что проверено в актуальном дубле; почему пробелов нет |
| `redirect_to_task` | Автор ушёл от задачи мысли | возврат к текущей задаче без новой темы и без смены правил агента |

Модель предлагает действие. Сервер проверяет схему, ссылки, актуальность состояния и допустимость перехода. Эта проверка **не** доказывает смысловое качество.

Текущий код (`reply` + `scriptProposal`) этому контракту не равен. Замена — этап V03, проводка в UI — V05.

## Тон и границы содержания

- Нет похвалы, ободрения и психологических оценок.
- Нет диагнозов и категоричных ярлыков.
- Один смысловой вопрос за ход.
- Вопрос связан с существенным пробелом. Уже отвеченное не повторять без причины.
- Запрещено выдумывать факты, мотивы, события, выводы и **готовую мысль автора**.
- Нет меню готовых смыслов «на выбор».
- Не копировать чужие истории, фразы и манеру.
- Не делать выводов о мимике, взгляде и интонации по одному тексту.
- Параметры «поддержка» и «инициатива помощника» отсутствуют.

## Достаточность материала

Достаточность **не** зависит от числа вопросов и **не** равна шаблону «хук — конфликт — мораль — CTA».

Оценка по замыслу автора:

- мысль понятна;
- оснований достаточно для этой мысли;
- нет противоречий, которые мешают донести замысел;
- задача следующей записи понятна **или** замысел уже донесён в актуальном дубле.

Не требовать историю для объяснения, мораль для наблюдения, конфликт или CTA для любого ролика. Короткая готовая мысль может сразу дать `suggest_take` или `content_sufficient`.

Ответ в чате не считается произнесённым в ролике. Разбор дубля — по актуальной расшифровке. Незавершённая расшифровка — не известный материал.

## Портрет

Портрет хранит **только общие** сведения и особенности, полезные для выбора вопросов и желаемого способа выражения.

Допустимо: общие цели, темы, аудитория; особенности формулирования; желаемый способ подачи; веса способов постановки вопросов; уверенность и основания наблюдений.

Недопустимо в производном портрете: подробности отдельных историй, похвала, диагнозы, ярлыки, «поддержка», ручные регуляторы весов.

Текущий замысел мысли важнее общих предположений портрета. Портрет **не** источник событий для сценария и **не** биографическая память.

Целевой UX (V04): пользователь смотрит портрет и продолжает разговор; прошлый портрет + новые ответы = новая ревизия; кнопка подтверждения не обязательна. На кандидате `4ac2863` confirm **ещё требуется** — это блокер, не норма контракта.

Без портрета основной цикл обязан работать.

## Глобальный портрет и данные мысли

| Слой | Что хранит | Чего не хранит |
|---|---|---|
| Глобальный портрет | устойчивые общие черты автора | факты и сюжеты конкретной мысли |
| Состояние мысли (`ThoughtState`, V02) | замысел, факты и пробелы **этой** мысли, рабочий дубль, задача дубля | общая биография, чужие мысли |
| Сообщения, исходники, версии | неизменяемая история | не заменяются reducer'ом |

«В этом ролике» не меняет глобальную настройку. Утверждение без ссылки на источник автора не становится фактом мысли.

На кандидате модели `ThoughtState` нет. До V02 источником правды остаются Reel, сообщения диалога, takes и ревизии текста.

## Итоговый дубль

Итоговый дубль выбирает **пользователь**. Агент может предложить рабочий дубль (`workingTake` / `suggest_take`), но не назначает `finalTakeId` за автора.

Просмотр старого дубля ≠ выбор его для работы. `finalTakeId` ≠ рабочий дубль.

## Завершение без отдельного итогового сценария

Предложенная политика (вынести на ревью V00, реализация не раньше V06):

- Отдельный итоговый сценарий **не обязателен** для завершения мысли.
- Если отдельного итогового сценария нет, **текст выбранного итогового дубля** фиксируется как итоговый текст мысли.
- Этот текст **не называть** заранее подготовленным сценарием.
- Существующие версии сценария и черновики **не затирать**.
- Три пользовательских статуса мысли не менять.

На кандидате завершение завязано на `finalTakeId` и часто на `finalScriptId`. Это старое поведение, не этот контракт.

Сценарий в ходе работы — опора из материала автора (основная мысль и порядок раскрытия), не дописка мотивов. «Помоги со сценарием» проходит через тот же анализ состояния: при пробеле — вопрос, при достаточности — предложение записи.

## Совместимость со старым поведением

Контракт **заменяет** в новом пути:

- свободный `reply` + `scriptProposal` как единственный контракт модели;
- лимит контекста `takes: { take: 2 }`;
- использование `selectedTakeId` / `finalTakeId` как неявного рабочего дубля;
- обязательный итоговый сценарий как условие завершения (если ревью примет политику V06);
- обязательный confirm портрета для работы цикла мысли (V04; не смешивать с непринятым Auth);
- управление циклом баллами legacy-разбора / playbook / scoring.

Контракт **сохраняет**:

- три статуса мысли для пользователя;
- историю сообщений, исходники, версии текста и записей;
- существующий редактор сценария и версии — без автозатирания;
- возможность записи без готового текста;
- голосовой ответ в чате отдельно от дубля;
- старые Review / Compare / баллы как архив, не как драйвер нового цикла;
- лендинг, Auth, оплату и I01 — вне этого цикла;
- изоляцию по `ownerUserId` (код есть; приёмка Auth не засчитана).

Старые данные не мигрировать в V00. Безопасный переход профиля и ThoughtState — на своих этапах, со сохранением старых ревизий.
