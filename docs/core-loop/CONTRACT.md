## Путь

Исходный материал
→ анализ состояния
→ `ask_question` **или** `suggest_take`
→ запись нового дубля
→ разбор актуальной расшифровки
→ `ask_question` **или** `content_sufficient`.

Правила развилки:

- До обработанного дубля `content_sufficient` **не используется**.
- Если исходный текст уже достаточен для записи, вернуть `suggest_take`.
- После разбора актуальной расшифровки: один вопрос **или** достаточность результата.
- Когда мысль донесена, агент не требует новых дублей без причины.
- **Итоговый дубль выбирает пользователь** (`finalTakeId`).

Камера не включается сама. Голосовое сообщение в диалоге и запись дубля — разные действия. Автор может продолжить разговор или перейти к записи сам.

## Действия агента

Внутренние действия. **Не статусы** мысли и не пользовательские стадии.

| Действие | Смысл | Обязательные поля (V03+) |
|---|---|---|
| `ask_question` | Один смысловой вопрос | вопрос; id пробела или причина уточнения; объяснение для аудита, почему ответ ещё не известен |
| `suggest_take` | Предложить записать следующий дубль | основная мысль из материала автора; задача записи; ссылки на основания |
| `content_sufficient` | Существенных пробелов нет **в обработанном дубле** | что проверено в актуальной расшифровке; почему пробелов нет |
| `redirect_to_task` | Автор ушёл от задачи мысли | возврат к текущей задаче без новой темы и без смены правил агента |

Модель предлагает действие. Сервер проверяет схему, ссылки, актуальность состояния и допустимость перехода. Эта проверка **не** доказывает смысловое качество.

V03 заменяет свободный `reply` + `scriptProposal` четырьмя действиями выше. `scriptProposal` в контракт V03 **не возвращается**. Сценарий — не пятое действие и не генерируется в текущем диалоге. Вкладка «Сценарий» и генерация по кнопке — **V05**, см. ниже и [`V05_SCENARIO_TAB_SPEC.md`](./V05_SCENARIO_TAB_SPEC.md).

## Вкладка сценария (V05)

V05 **planned / not started**. Это контракт будущего этапа, не начало реализации. BASE для V05 не назначен.

Сценарий — необязательная опора для записи следующего дубля. Он не обязательный результат мысли, не финальный текст пользователя, не сообщение диалога, не автоматическое завершение, не замена живого дубля и не основание менять `Reel.status`. Запись доступна без сценария.

Создаётся **только** по явному нажатию кнопки во вкладке «Сценарий». Самостоятельная генерация после ответа, `suggest_take`, нового дубля или открытия вкладки запрещена.

В рабочем пространстве мысли отдельные вкладки: «Диалог» (раскрытие и вопросы) и «Сценарий» (готовность, генерация, правка черновика). Переход к записи — отдельное действие пользователя. Вкладка «Сценарий» не второй чат и не ведёт свою историю вопросов. Обе вкладки делят один `ThoughtState`, один рабочий дубль и одну историю материалов.

Состояния вкладки: `empty`, `not_ready`, `ready_to_generate`, `generating`, `ready`, `stale`, `conflict`, `error`.

Перед генерацией сервер проверяет замысел, достаточность подтверждённого авторского материала для этого замысла (позиция, наблюдение, факт, пример или личный опыт — не обязательный объект `facts`), критические пробелы, задачу дубля, актуальность состояния, согласованность рабочего дубля и точную ревизию расшифровки, если она используется. Сообщения диалога сами по себе не источники сценария: в черновик попадают только реплики, на которые ссылаются принятые факты, решения или другие основания `ThoughtState`. Недостаток информации для идеального текста сам по себе запись не блокирует. Блокируется генерация, если прямую речь нельзя собрать без додумывания содержания. Тогда черновик не создаётся, показывается одна причина, один следующий вопрос и переход «Ответить на вопрос» во вкладку «Диалог».

Черновик — текст прямой речи. Источники, версии, `stale`, снимок генерации, 409 и приёмка — в [`V05_SCENARIO_TAB_SPEC.md`](./V05_SCENARIO_TAB_SPEC.md). Генерация не пишет `script_proposal` в ленту диалога. Камера при переходе к записи не включается сама.

## Статусы мысли

Фактические внутренние `ReelStatus`: `idea`, `in_progress`, `ready_to_record`, `completed`, `archived`.
`draft` и `active` — legacy aliases (`draft` → `idea`, `active` → `in_progress`). В схеме Postgres default колонки на `f971a7f` всё ещё `"draft"`.

Целевые пользовательские группы основного цикла:

- «Не завершена»
- «В работе»
- «Успешно завершена»

`ready_to_record` и `archived` **не показывать** как дополнительные пользовательские стадии основного цикла. Архив — служебное скрытие, не шаг ядра.

## Тон и границы содержания

- Нет похвалы, ободрения и психологических оценок.
- Нет диагнозов и категоричных ярлыков.
- Один смысловой вопрос за ход.
- Вопрос связан с существенным пробелом. Уже отвеченное не повторять без причины.
- Запрещено выдумывать факты, мотивы, события, выводы и **готовую мысль автора**.
- Нет меню готовых смыслов «на выбор».
- Не копировать чужие истории, фразы и манеру.
- Не делать выводов о мимике, взгляде и интонации по одному тексту.
- Параметры «поддержка» и «инициатива помощника» отсутствуют.

## Достаточность материала

Достаточность **не** зависит от числа вопросов и **не** равна шаблону «хук — конфликт — мораль — CTA».

Оценка по замыслу автора:

- мысль понятна;
- оснований достаточно для этой мысли;
- нет противоречий, которые мешают донести замысел;
- задача следующей записи понятна **или** замысел уже донесён в актуальном дубле.

Не требовать историю для объяснения, мораль для наблюдения, конфликт или CTA для любого ролика.

Короткая готовая **исходная** мысль до записи даёт `suggest_take`, не `content_sufficient`.

Ответ в чате не считается произнесённым в ролике. Разбор дубля — по актуальной расшифровке. Незавершённая расшифровка — не известный материал.

## Портрет (V04)

Портрет — этап **V04 этого цикла**, не вынесенный «только I05». Точный контракт: [`V04_ADR.md`](./V04_ADR.md). Продукт V04 не начат; на `V04_BASE_SHA` confirm ещё в коде.

Целевой UX:

- пользователь просматривает портрет и продолжает разговор;
- прямое общее утверждение (цель блога, аудитория, постоянная тема, явная граница) может обновить портрет из одного ответа;
- производные особенности коммуникации накапливаются как наблюдения с источником, уверенностью и системным весом; одна случайная реплика характеристику не делает;
- новая `ProfileRevision` только если изменился отображаемый срез; payload старых ревизий не менять;
- журнал оснований — события `v04-event-1` в `AiCall.resultJson`, не техническая ревизия;
- отдельного подтверждения нет; старый pending не публиковать автоматически;
- подробности конкретных мыслей в глобальный портрет не попадают.

Допустимо хранить: прямые категории `blog_goal`, `general_audience`, `standing_topic`, `explicit_boundary`; производные слоты закрытого enum; принятые events.

Недопустимо как категории: настроение, похвала, диагноз, «тип автора». Модель возвращает `kind`: `apply_update` \| `no_change` \| `thought_specific`. Сервер проверяет структуру, источники, один `evidenceMessageId` на слот `(category, value)` за всю историю, пороги `0.5` / `3` / `1` и выбор допущенного слота (макс. вес; ничья — текущее value). Смысл `value` не толкует. Текущий замысел мысли важнее портрета. Портрет не источник событий сценария. Без портрета цикл обязан работать.

На BASE и на `f971a7f` confirm ещё требуется (`confirmProfilePortrait` / `readyToConfirm`) — факт кода, который продуктовые коммиты V04 снимают.

## Глобальный портрет и данные мысли

| Слой | Что хранит | Чего не хранит |
|---|---|---|
| Глобальный портрет | устойчивые общие черты автора | факты и сюжеты конкретной мысли |
| Состояние мысли (`ThoughtState`, **V02**) | замысел, факты и пробелы **этой** мысли, рабочий дубль, задача дубля | общая биография |
| Сообщения, исходники, версии | неизменяемая история | не заменяются reducer'ом |

«В этом ролике» не меняет глобальную настройку. Утверждение без ссылки на источник автора не становится фактом мысли.

На `f971a7f` модели `ThoughtState` нет. На ветке V02 состояние мысли хранится в `ThoughtState`; сообщения, исходники и версии остаются историей.

## Inflight и идемпотентность

Целевой контракт (ввод в код на **V01**):

- ключ включает `ownerUserId`, object type, object id, operation type и `idempotencyKey`;
- разные пользователи не разделяют Promise;
- разные объекты не разделяют Promise;
- повтор одной операции дедуплицируется;
- конфликт разных версий состояния возвращает 409;
- повтор не создаёт второй вызов модели.

На `f971a7f`: `withAiInflight` ключи `dialogue:${reelId}:${key}` и `profile-dialogue:${key}`; одинаковый ключ возвращает общий Promise; 409 по версии состояния не выставляется; разные пользователи с тем же `reelId`/`key` делят Promise процесса.

## Завершение (политика, код только на V06)

- `finalTakeId` выбирает пользователь.
- `finalScriptId` не обязателен.
- Итоговый текст ссылается на **точную выбранную ревизию расшифровки** `finalTakeId`.
- Итоговый текст **не называется сценарием**.
- Сценарии и черновики не затираются.
- Изменение реализуется **только на V06**.

На `f971a7f` `thoughtCompletionGate` **всегда** требует и `finalTakeId`, и `finalScriptId`.
`backfillFinalTakeIds` — служебная функция (копирует `selectedTakeId` → пустой `finalTakeId`), не пользовательский выбор итога.

## Совместимость со старым поведением

Контракт **заменяет** в новом пути:

- свободный `reply` + `scriptProposal` как единственный контракт модели (V03);
- лимит контекста `takes: { take: 2 }` (V01);
- `selectedTakeId` / `finalTakeId` как неявный рабочий дубль (V01);
- обязательный `finalScriptId` для завершения (V06);
- обязательный confirm новой ревизии портрета (V04);
- управление циклом баллами legacy-разбора / playbook / scoring (V06–V07).

Контракт **сохраняет**:

- три пользовательские группы статусов основного цикла;
- внутренние `ReelStatus` и aliases без показа `ready_to_record` / `archived` как стадий ядра;
- историю сообщений, исходники, версии текста и записей;
- существующий редактор сценария — без автозатирания;
- запись без готового текста;
- голосовой ответ в чате отдельно от дубля;
- старые Review / Compare / баллы как архив;
- лендинг и Auth (приняты) — вне смены логики V00.

Старые данные не мигрировать в V00.
