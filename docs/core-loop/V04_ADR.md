## Граница ответственности

1. Модель классифицирует смысл реплики и возвращает **строго структурированный** кандидат. Похвала, поддержка, диагноз, настроение, деталь мысли и выдуманное событие модель **не** кладёт в разрешённые категории: она возвращает `no_change` или `scope=thought_specific`.
2. Сервер **не** анализирует произвольный текст семантически. Поле `value` для прямых категорий — непрозрачная строка: сервер проверяет тип и длину, не смысл.
3. Запреты похвалы, диагноза, настроения и деталей мысли обеспечиваются контрактом модели, **закрытыми enum** и **разрешёнными переходами**, а не разбором содержания `value`.
4. Сервер проверяет только перечисленное ниже. Нарушение — отказ кандидата, журнал и действующий портрет не меняются.

## Кандидат

Обязательные поля: `category`, `value`, `scope`, `evidenceType`, `evidenceMessageIds`, `confidence`, `operation`.

`confidence` — конечное число, диапазон **[0, 1]** включительно. Вне диапазона, `NaN`, не число — отказ.

`evidenceMessageIds` — массив строк. Пустой, кроме `no_change`. Дубликаты внутри массива — отказ.

## Что проверяет сервер

Сервер **не** читает смысл `value`. Он проверяет:

- `category` ∈ прямого или производного enum;
- для производной категории `value` ∈ таблице выше; для прямой — длина строки;
- `scope`, `evidenceType`, `operation` ∈ своих enum;
- `confidence` ∈ [0, 1];
- каждый id в `evidenceMessageIds` существует;
- роль сообщения — `user`;
- владелец сообщения — текущий пользователь профиля;
- `thread.scope = profile` и `thread.profileId` — профиль автора;
- нет id из диалога мысли (`scope=thought` / `reelId`);
- нет повторных id внутри массива;
- id ещё не записан в журнал этого слота для той же роли основания (support / oppose);
- совместимость `operation` / `category` / `evidenceType` / `scope` (таблица ниже);
- минимальное число независимых оснований для операции;
- детерминированные пороги веса после применения.

`scope=thought_specific`: кандидат структурно может быть принят как «не применять». Глобальный журнал, действующий портрет и `ProfileRevision` не меняются. Так модель помечает деталь мысли, не используя прямую/производную публикацию.

## Совместимость operation / category / evidenceType

| operation | category | evidenceType | scope для применения | Мин. независимых id |
|---|---|---|---|---|
| `replace_explicit` | прямая | `explicit_statement` | `global` | 1 |
| `add_observation` | производная | `behavioral_observation` | `global` | 1, слот может быть новым |
| `strengthen` | производная | `behavioral_observation` | `global` | 1 новых id; слот уже есть (≥1 записи) |
| `weaken` | производная | `behavioral_observation` | `global` | 1 новых id; слот уже есть |
| `no_change` | любая из enum | любой из enum | любой из enum | 0; записей нет |

Любая другая комбинация — отказ. В том числе `replace_explicit` на производной категории и `behavioral_observation` на прямой.

## Слот, вес, пороги

Слот производной особенности: пара `(category, value)`.

Независимое основание — уникальный `evidenceMessageId`, прошедший проверки источников.

- `support_n` — число уникальных id, записанных как support, у которых `confidence >= 0.5`
- `oppose_n` — число уникальных id, записанных как oppose, у которых `confidence >= 0.5`
- `system_weight = support_n - oppose_n`

Основание с `confidence < 0.5` пишется в журнал и **не** меняет `system_weight`.

Константы (целые, без эвристик):

- `COUNTING_MIN_CONFIDENCE = 0.5`
- `PUBLISH_THRESHOLD = 3`
- `REMOVE_THRESHOLD = 1`

Гистерезис одного слота:

- не опубликован → опубликован, когда `system_weight >= 3`
- опубликован → снят, когда `system_weight <= 1`
- при `2 <= system_weight` и слот уже опубликован — остаётся опубликован

На категорию в действующем портрете не больше одного `value`. Если второй слот той же категории пересекает порог публикации: он становится отображаемым **только** если его `system_weight` строго больше веса текущего опубликованного слота; иначе остаётся в журнале.

Пользователь веса не видит и не правит.

## Правила add_observation, strengthen, weaken

Общее: после структурных проверок id дописываются в журнал слота. История не затирается.

**`add_observation`.** Создаёт слот при необходимости. Id идут в support. Действующий портрет меняется только если этот слот впервые пересекает `PUBLISH_THRESHOLD` (или вытесняет отображаемое значение по правилу выше).

**`strengthen`.** Слот должен существовать. Новые id → support. Если слот уже опубликован и отображаемое значение то же — новой `ProfileRevision` нет, даже если вес вырос.

**`weaken`.** Слот должен существовать. Новые id → oppose. Характеристика не затирается автоматически: снимается только при `system_weight <= REMOVE_THRESHOLD` у опубликованного слота. История oppose сохраняется.

**`replace_explicit`.** Записывает отображаемое прямое сведение. Одна валидная реплика достаточна. Повтор с тем же нормализованным `value` — без новой ревизии.

**`no_change`.** Нет записей.

## Значимое изменение → новая ProfileRevision

Новая ревизия **только** если после принятого кандидата верно одно:

- принято или заменено прямое общее сведение (нормализованный `value` категории изменился);
- производная особенность пересекла порог публикации и появилась в действующем портрете;
- опубликованная особенность пересекла порог удаления и исчезла из действующего портрета;
- изменилось отображаемое значение действующего портрета (другой `value` той же категории).

Не создают `ProfileRevision`:

- слабое основание (`confidence < 0.5`);
- повтор id (отказ) или повтор того же прямого `value`;
- `add_observation` / `strengthen` ниже порога публикации;
- `weaken` без пересечения `REMOVE_THRESHOLD`;
- рост или падение внутреннего веса при том же отображаемом срезе;
- `no_change` и `thought_specific`.

Confirm нет. Модель предлагает кандидата, сервер применяет таблицы и пороги.
