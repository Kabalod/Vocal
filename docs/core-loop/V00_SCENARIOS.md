# V00 — сценарии ядра (как есть на кандидате)

Сценарии для ревью, не для прогона как приёмки продукта. Поведение — дерево `4ac2863`, не грязные `thought-opening` / `dialogue-reply`.

## 1. Открыть мысль и диалог

Автор залогинен, открывает карточку мысли, GET диалога.

**Сейчас:** тред `DialogueThread` scope `reel`, сообщения `DialogueMessage`. Автооткрытия первичного разбора **в дереве HEAD нет** (оно живёт в незакоммиченном `thought-opening.ts`).

**Риск:** пустой чат, пока автор или другой путь не создаст review/вопрос.

## 2. Ответ в диалоге

POST сообщения → `withAiInflight('dialogue:${reelId}:${key}')` + дневной бюджет → JSON `reply` + опционально `scriptProposal`.

**Сейчас:** контекст материала из **двух** takes по номеру + `selectedTakeId` если он в этой двойке.

**Риск:** выбранный третий+ дубль не виден модели.

## 3. Просьба сценария в том же чате

Автор просит основу / прямую речь.

**Сейчас:** системный промпт велит собрать `scriptProposal` одной строкой; есть `requestScriptHelp`. Параллельно живёт generate script API.

**Цель плана V02:** один ход, без второго чата. Не изобретать факты.

## 4. Выбор дубля и завершение

Автор ставит итоговый дубль/сценарий, `status: completed`.

**Сейчас:** `finalTakeId` / `finalScriptId` / `selectedTakeId`. Backfill копирует selected → final если final пуст. Нет `suggest_take`, нет `workingTake`.

**Риск:** «рабочий» и «итоговый» дубль смешаны в голове автора и в коде.

## 5. Повторный клик / двойной POST

Один и тот же inflight-ключ возвращает тот же промис. Другой idempotency/key — второй вызов модели.

**Сейчас:** не 409.

## 6. Профиль (вне цикла, чтобы не сломать)

Диалог профиля + `confirmProfilePortrait`.

**Сейчас:** confirm обязателен для «готового» портрета. Ядро мысли не должно это снимать.

## 7. Чужой ресурс

`ownerUserId()` + `withApiUser`. Мысль другого пользователя — 404/запрет, не «local».

**Сейчас:** код изоляции есть; приёмка Auth не засчитана.
