## Продуктовая роль

Сценарий — необязательная опора для записи следующего дубля.

Он **не** является:

- обязательным результатом работы с мыслью;
- финальным текстом пользователя;
- сообщением диалога;
- автоматическим завершением мысли;
- заменой живого дубля;
- основанием автоматически менять `Reel.status`.

Пользователь может перейти к записи без сценария.

Сценарий создаётся **только** по явному нажатию кнопки пользователя во вкладке «Сценарий». Самостоятельная генерация после ответа, `suggest_take`, нового дубля или открытия вкладки **запрещена**.

## Разделение интерфейса

В рабочем пространстве мысли отдельные вкладки:

- «Диалог» — раскрытие мысли и уточняющие вопросы;
- «Сценарий» — проверка готовности, генерация и редактирование черновика;
- переход к записи — отдельное действие пользователя.

Вкладка «Сценарий» не является вторым чатом и не ведёт собственную историю вопросов.

Обе вкладки используют один `ThoughtState`, один рабочий дубль и одну историю материалов мысли.

## Состояния вкладки

| Состояние | Смысл |
|---|---|
| `empty` | сценария ещё нет |
| `not_ready` | информации недостаточно |
| `ready_to_generate` | данных достаточно для генерации |
| `generating` | запрос выполняется |
| `ready` | черновик создан и доступен для редактирования |
| `stale` | после генерации появились новые ответы, изменения состояния или новый рабочий дубль |
| `conflict` | исходные данные изменились во время генерации |
| `error` | генерация завершилась технической ошибкой |

## Проверка готовности

Перед генерацией сервер проверяет:

- понятен ли замысел мысли;
- достаточно ли подтверждённого авторского материала для выбранного замысла: позиции, наблюдения, факта, примера или личного опыта — в зависимости от типа мысли;
- нет ли критического открытого пробела;
- понятна ли задача следующего дубля;
- существует ли актуальное состояние мысли;
- согласован ли рабочий дубль;
- если используется расшифровка — выбрана ли точная актуальная ревизия.

Readiness **не** требует механически хотя бы один объект `facts`. Короткая ясная позиция или наблюдение без истории и отдельного примера может быть достаточной. Блокируется генерация только тогда, когда прямую речь нельзя составить без придумывания содержания.

Недостаток информации для идеального текста сам по себе **не** блокирует запись. Блокируются только случаи, когда прямую речь нельзя сформировать без додумывания позиции, фактов или вывода автора.

## Поведение при недостатке информации

Если критической информации недостаточно:

- сценарий не создаётся;
- вызов генерации не должен сохранять пустой или частичный черновик;
- интерфейс показывает одну конкретную причину;
- показывается один следующий вопрос;
- доступна кнопка «Ответить на вопрос»;
- кнопка переводит пользователя во вкладку «Диалог»;
- нужный вопрос отображается в диалоге;
- поле ответа получает фокус.

Не показывать список из нескольких вопросов и не предлагать готовые смыслы на выбор.

После ответа готовность проверяется заново.

## Источники сценария

Сообщения диалога — неизменяемая история. Они **не** являются свободным источником содержания сценария.

Черновик прямой речи формируется только из:

1. подтверждённых фактов `ThoughtState` и других структурированных оснований состояния (позиция, решения, задача дубля);
2. пользовательских сообщений диалога **только если** на них ссылается принятый `ThoughtFact`, решение или иное структурированное основание `ThoughtState`;
3. актуальной выбранной ревизии рабочего дубля;
4. решений и задачи следующего дубля;
5. релевантных формулировок предыдущих дублей;
6. портрета автора — только для способа подачи, но не как источника событий;
7. библиотеки приёмов после V07 — только как ремесленный приём, не как источник содержания.

Сообщение без такой ссылки можно использовать для продолжения диалога, но не как содержание сценария. Команды (`снимай`, `хватит`), системные реплики, посторонний вопрос и сообщение, после которого агент вернул `redirect_to_task`, в сценарий не попадают. Сообщение ассистента не становится содержательным источником.

Приоритет имеют актуальное состояние мысли, структурированные основания и выбранная ревизия рабочего дубля.

Запрещено механически объединять все расшифровки в один текст.

## Требования к результату

Черновик должен быть текстом прямой речи, который пользователь может произнести в следующем дубле.

Разрешено:

- упорядочивать подтверждённый материал;
- сокращать повторы;
- связывать пользовательские формулировки;
- сохранять характерные слова автора;
- предлагать нейтральные связки между подтверждёнными частями.

Запрещено:

- придумывать события, факты, мотивы и выводы;
- писать позицию, которую пользователь не выражал;
- копировать чужие истории и формулировки;
- автоматически добавлять CTA;
- требовать конфликт, мораль или историю для каждого ролика;
- менять глобальный портрет на основании одного сценария;
- называть черновик единственно правильной версией.

## Сохранение и версии

Первая генерация создаёт отдельную версию черновика.

Повторная генерация:

- не перезаписывает предыдущую версию;
- создаёт новую версию;
- сохраняет предыдущие версии;
- не уничтожает ручные изменения пользователя;
- не заменяет сценарий автоматически после новых данных.

Пользователь может:

- редактировать текст;
- сохранять ручные изменения;
- переключаться между версиями;
- оставить текущую версию;
- создать обновлённую версию;
- перейти к записи;
- записывать без сценария.

## Новые ответы и дубли

Если после генерации появились:

- новое сообщение пользователя;
- новая подтверждённая информация;
- изменение `ThoughtState`;
- другой рабочий дубль;
- новая выбранная ревизия расшифровки,

текущий черновик остаётся неизменным и получает состояние `stale`.

Интерфейс показывает: «После создания сценария появились новые данные».

Доступные действия:

- «Оставить текущую версию»;
- «Обновить сценарий».

Обновление создаёт новую версию, а не изменяет старую.

## Снимок генерации и защита от гонок

Запрос генерации фиксирует минимум:

- `ownerUserId`;
- `reelId`;
- `ThoughtState.revision`;
- `workingTakeId`;
- `selectedTranscriptId`;
- версию диалога;
- идентификатор или версию редактируемого черновика;
- источники, использованные при сборке промпта;
- `idempotencyKey`.

Перед сохранением результата сервер повторно проверяет этот снимок.

Если состояние изменилось:

- результат модели не сохраняется;
- существующий черновик не меняется;
- возвращается 409;
- пользователь видит предложение повторить генерацию по новым данным.

Повтор одного запроса не должен создавать несколько версий или несколько вызовов модели.

Разные пользователи и разные мысли не должны разделять inflight-запрос.

## Связь с диалогом

Генерация сценария не создаёт `script_proposal` в ленте диалога.

В диалоге можно показать только служебное событие или ссылку на созданную версию, если это понадобится UI, но полный сценарий живёт во вкладке «Сценарий».

V03 продолжает возвращать только:

- `ask_question`;
- `suggest_take`;
- `content_sufficient`;
- `redirect_to_task`.

Сценарий не является пятым действием V03.

## Переход к записи

Из готового черновика пользователь может нажать «Перейти к записи».

При этом:

- камера и микрофон не включаются автоматически;
- пользователь выбирает текст, аудио или видео;
- фиксируется версия сценария, использованная как опора;
- новый дубль сохраняется отдельно;
- сценарий не считается произнесённым материалом;
- дальнейший анализ выполняется по фактической расшифровке дубля.

Переход к записи также доступен без сценария.
