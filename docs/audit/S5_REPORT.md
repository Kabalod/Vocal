## Найденные замечания (код не менялся)
1. **Мягкий 404:** страница чужой/удалённой мысли отдаёт HTTP 200 с текстом «Мысль не найдена» (стриминг при `loading.tsx`). Данные не утекают, API отдаёт настоящий 404.
2. В ошибке STT в интерфейсе виден служебный код `Код: NO_SPEECH|stt`.
3. Запись голоса: однократно клик по «Продолжить с Vocal» сразу после «Завершить запись» не прошёл за 8 с (с паузой 2 с проходит стабильно). Возможна гонка готовности записи; не воспроизводил отдельно.
4. 1 из 4 ходов живой модели падает на валидации ответа (см. выше) — кандидат на повтор/ослабление проверки; решение за владельцем.
5. `next build` с `VOCAL_UI_TEST_DB=1` в окружении падает (`Нужен TEST_DATABASE_URL`), собирать нужно без этой переменной (в Docker она не попадает).

## Блокеры закрытого запуска (добавлено 07.10.2026)

1. **Лимит провайдера: 200 000 токенов в сутки на аккаунт Groq (суточный скользящий лимит, тариф `on_demand`), блокер запуска.** Проверено прямым запросом: «tokens per day (TPD): Limit 200000, Used 199661». Одного диалога из 6 ходов с диагностикой и двумя сборками хватает на ≈ 12–16 тыс. токенов (≈ 2,1 тыс. на ход), то есть на весь аккаунт приходится порядка 12–16 таких диалогов в сутки. **Для нескольких авторов этого не хватит**: лимит шлюза S1 (200 000 токенов на пользователя) выше, чем у провайдера на весь аккаунт, поэтому при двух и более активных авторах провайдер остановит работу раньше шлюза. Платные тарифы и API владельцем исключены; пути снижения: сократить расход на ход (статичные правила в запросе занимают ≈ 800 токенов из ≈ 1400 входных), другой бесплатный провайдер или отдельный ключ на автора (нужно решение владельца). Подробности: `R5_REPORT.md`.
2. **SMTP не выбран** (S0.5 отложен): регистрация, подтверждение почты и сброс пароля на живой среде не проверены и не могут быть проверены.
3. Живой Supabase (удаление аккаунта, `public.profiles`, бакет, два пользователя) не проверялся: нет `SUPABASE_SERVICE_ROLE_KEY` и `DIRECT_URL`.
