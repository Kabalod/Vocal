## Проверки (Node 22, встроенный Postgres, Chromium; Docker в среде нет)

- `tsc` — ок; `next lint` — 0 ошибок; **`next build` с lint и CI-подобными заглушками окружения — ок**.
- Все файлы runner (кроме live): **398 тестов, 398 pass, 0 fail**, ~7 мин 51 с.
- **Рестарт во время STT (настоящие процессы)**, `tests/s4-restart.test.ts`:
  1. SIGKILL в середине STT → после истечения lease задание подхвачено, `done`, ровно одна оригинальная расшифровка, медиафайл на месте, STT вызван 2 раза (убитый и повтор), завершённое задание повторно не обрабатывается;
  2. SIGTERM → активное задание доработало, процесс вышел с кодом 0 (`drained=true`);
  3. SIGTERM при задании дольше grace → lease снят (`released=1`), следующий процесс забирает его сразу, хотя lease был 10 минут. Мутация (убрать снятие lease) роняет тест 3.
- **Восстановление из бэкапа по runbook (реальный прогон)**: исходная БД Postgres 16 с миграциями в `public`, 4 мысли, 2 медиафайла → `backup.sh` → `restore.sh` в пустую БД и каталог → `verify-restore.sh`: счётчики совпали, медиа побайтно идентично. Отрицательные проверки: повторное восстановление отказывает, испорченный дамп не проходит `sha256sum`, пустая БД и пропавший файл дают ненулевой код. Прогон нашёл два дефекта скриптов (`CREATE SCHEMA public` в пустой БД; `verify` печатал «ok» при ошибке запросов) — исправлены.
