## 1. Архитектура и пользовательский цикл

Одно Next.js 15 приложение: UI, API, очередь медиа и ffmpeg в одном Node-процессе. PostgreSQL через Prisma, вход через Supabase Auth, модели и STT — Groq (опционально xAI), только с сервера. **К**

Файлы дублей пишутся на **локальный диск** (`storage/videos`, `storage/audio`), не в Supabase Storage. Бакет `vocal-private` только читается для путей с префиксом `vocal-private:`; кода записи туда нет (`src/lib/storage.ts`, `src/lib/takes.ts` → `saveUploadedTake`, `src/lib/media-access.ts`). **К**

Почти все связи в схеме — `onDelete: Restrict`: удаление мысли или автора требует явного упорядоченного удаления. **К**

Цикл автора, как реализован:

1. **Создать мысль** — в UI только текстом: `NewThoughtSheet` → `POST /api/thoughts`. `POST /api/thoughts/media` → `createThoughtFromMedia` есть, но из UI не вызывается. **К**
2. **Диалог мысли** — `ThoughtDialogue` → `POST /api/thoughts/:id/dialogue` → `sendDialogueMessage` / `sendDialogueVoice` (`src/lib/dialogue.ts`): `turnKey`, exec-lease в `AiCall`, снимок материала, C00, карточки V07 в снимке хода. **К**
3. **Сценарий по кнопке** — `ScriptEditor` → `POST /api/reels/:id/scripts/generate` → `src/lib/v05-script.ts`. **К** (поведение V05 — **Д**)
4. **Дубль** — `RecordingView` / `TakeUploadDropzone` → `POST /api/uploads` (`reelId`, `process=1`) → `saveUploadedTake` → `ensureJobForTake` → `enqueueJob` → `processJob`: ffmpeg → STT → `publishMediaJobResult` (Job FOR UPDATE + `leaseOwner`, затем Reel FOR UPDATE) → title → `completeJob`. **К**
5. **Обсуждение расшифровки** — диалог читает выбранную ревизию рабочего дубля; правка — `TranscriptEditor` → `/api/takes/:id/transcript`. **К**
6. **Завершение** — `PATCH /api/reels/:id` с явным `finalTakeId`; `CompletionSummary` → `/api/reels/:id/export`. **К** (правила V06 — **Д**)

Портрет: `/profile` → `ProfileConversation` → `POST /api/profile/dialogue` → `sendProfileMessage` → `commitV04ProfileTurn` под `CreatorProfile FOR UPDATE`. **К**
