# S2 (I07-B) — удаление данных пользователя: отчёт

Статус: **кандидат**, не приёмка. Ветка `feat/s2-data-deletion` от `feat/s3-entry-cleanup` (BASE = `1fdedec`). Закрывает п. 3 аудита. Контракт: [`S2_CONTRACT.md`](./S2_CONTRACT.md).

## Что сделано

- `src/lib/data-deletion.ts`: `deleteThought`, `deleteTake`, `deleteAccountData`, `sweepOrphanMedia`, tombstone ключа создания.
- Маршруты: `DELETE /api/reels/:id`, `DELETE /api/takes/:id`, `DELETE /api/account` (подтверждение `{"confirm":"УДАЛИТЬ"}`; до удаления проверяется, что сервер умеет удалить вход, иначе 503 и данные не тронуты).
- `src/lib/supabase/service.ts` (только сервер): объекты бакета `vocal-private/<userId>/`, `public.profiles`, `auth.users` через service role. Ключ в клиент и логи не попадает.
- UI (`DeleteActions.tsx`): «Удалить мысль» (шапка мысли), «Удалить дубль» (карточка дубля), «Удалить аккаунт» (профиль, ввод фразы «УДАЛИТЬ»). Фокус в окне подтверждения — на безопасной кнопке.
- Replay: повтор ключа создания удалённой мысли (текст и медиа) → `410 THOUGHT_DELETED`.
- Файлы удаляются после коммита; сбой или запоздалая запись воркера не теряет файл: stateless-чистильщик по ссылкам из БД (старт и каждые 6 ч, файлы младше 1 часа не трогаются).
- Дополнительно (S0.6): из промпта сценария `v05-script.ts` убраны «Замысел/Аудитория карточки» (в S3 я убрал их только из диалога; грепом пропустил эту вторую точку).
