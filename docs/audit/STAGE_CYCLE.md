# Этап R: новый цикл «дубль → сценарий → вопросы → сборка»

Решение владельца 07.10.2026. Это **новый этап доработок**, он не заменяет S0–S5 из [`STAGES.md`](./STAGES.md) и не меняет принятые статусы V00–V07, C00, медиа-пути, Auth. Он **переопределяет продуктовую логику** V03/V05 в пределах, названных ниже. Реализация и приёмка отдельно; этот документ только задаёт объём.

## 1. Продуктовая логика

Автор не разбирается в промптах и генерации. Он разговаривает с сервисом, сервис структурирует мысль.

1. Автор даёт **дубль**: текстом, голосом или видео.
2. Из дубля автоматически создаётся **сценарий-основа** (`ScriptVersion`, тип `from_take`): очищенный транскрипт без вызова модели, ссылка на дубль в `sourcesJson`.
3. Диалог сразу задаёт **уточняющие вопросы** по этому дублю. Автор отвечает обычными словами.
4. Ответы копятся **скрыто** (`ThoughtState`: факты, пробелы). Списка ответов в интерфейсе нет, править его нельзя. Поправить сервис можно репликой в диалоге (механизм C00 `correct_thought`).
5. Перед сборкой сервис говорит одну человеческую реплику: «Я понял так: … Собрать сценарий?». Автор отвечает словами.
6. Кнопка **«Сгенерировать сценарий»** (одна, без настроек). Вход генерации: **последний дубль автора + ответы**. Выход: новый текст сценария и пара человеческих фраз «что изменил и почему». Модель не пишет за автора: сохраняет его формулировки.
7. Автор записывает следующий дубль, цикл повторяется. Основой всегда служит последний дубль, а не цепочка сгенерированных текстов.

Три объекта остаются раздельными: **транскрипт** (что сказано, не меняется), **сценарий** (опора для следующего дубля), **итоговый текст финального дубля**.

## 2. Что меняется относительно принятого канона

| Было (V03/V05) | Станет |
|---|---|
| Первая мысль — текстовый дубль №1, сценария нет | Первый дубль любого вида сразу даёт сценарий-основу |
| Сценарий появляется только по явной кнопке | Основа создаётся автоматически; кнопка собирает улучшенную версию |
| Диалог «раскрой мысль» | Диалог «улучши сценарий» (вопросы от пробелов дубля) |
| Дубль только текстом из UI | Текст, голос, видео (опирается на S3) |

Статусы в `AGENTS.md` и `ROADMAP.md` не меняются. Исполнитель этапа R пишет «кандидат R на `<SHA>`».

## 3. Зависимости и порядок

R1 требует **S3** (вход голосом и видео), иначе цикл работает только для текста. Запуск живым авторам требует **S1** (шлюз, лимиты) и **S2** (удаление). Новые вызовы модели (диагностика дубля, сборка) идут только через шлюз S1.

| Шаг | Содержание | Зависит от |
|---|---|---|
| R1 | Сценарий-основа из дубля: `from_take`, без модели, версии ссылаются на дубль | S3 для голоса и видео; для текста можно сразу |
| R2 | Диалог по сценарию: диагностика дубля (тип записи, тезис или тема, шаги, опоры, обещание и вывод, неопределённости), вопросы от пробелов | R1, S1 |
| R3 | Поведение вне темы и служебные id: возврат к вопросу, справка о продукте без модели, короткие индексы вместо cuid, счётчик подряд оффтопа | R2 |
| R4 | Сборка: реплика «Я понял так…», кнопка, вход «последний дубль + ответы», выход «текст + что изменил», запрет попадания цитат корпуса и `sourceReelIds` в текст | R2, R3 |
| R5 | Проверка на живой модели малой серией (набор транскриптов корпуса как внутренние входы, не продукт) и эксперимент «с карточками / без» после того, как цикл работает без карточек | R4, S1 |

Карточки (I06) в R1–R4 не нужны: диалог обязан работать без них. Подключать только по итогам R5.

## 4. Решения, принятые по умолчанию

- Основа равна очищенному транскрипту, без модели (дёшево, без искажений).
- Автор не видит список ответов и не правит его; контроль результата идёт через сгенерированный текст и реплики диалога.
- Новый дубль создаёт новую основу; сгенерированные версии ветвятся от основы через `parentId`.
- Оффтоп: вопрос о продукте получает короткий ответ из статичной справки; вопрос не по теме получает возврат к самому важному открытому пробелу; после 2–3 оффтопных сообщений подряд сервис предлагает продолжить мысль или отложить.

Если владелец решит иначе, этот раздел правится до начала R1.
