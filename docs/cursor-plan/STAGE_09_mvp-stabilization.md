добавления новых продуктовых возможностей.

**Предлагаемая ветка:** `feat/personal-mvp-09-mvp-stabilization`.

## Обязательные правила выполнения

Репозиторий: `Kabalod/Vocal`. План подготовлен по проверенному коммиту
`b59e78a0a177442dd7fc30e02217153c634eb98f`. Это исходная точка исследования,
а не команда откатить проект. Работай поверх принятого этапа 8.

1. Прочитай применимые AGENTS.md, README.md, SPEC.md, package.json,
   docs/PERSONAL_MVP.md и docs/IMPLEMENTATION_STATUS.md, если они есть.
2. Проверь текущую ветку, HEAD и незакоммиченные изменения. Не удаляй и не
   перезаписывай чужую работу. Зафиксируй BASE_SHA перед изменениями этапа.
3. Выполняй только этот этап. Сначала проверь, нет ли уже эквивалентной
   реализации. Расширяй её вместо дублирования.
4. Сохраняй Next.js, TypeScript, Prisma, SQLite и существующий Groq-адаптер.
   Не переписывай приложение, не меняй провайдера и не добавляй зависимости
   без конкретной необходимости. Объясняй необходимые отклонения в отчёте.
5. Не теряй старые видео, аудио, тексты и разборы. Перед миграцией сделай
   согласованную резервную копию при остановленных записях в БД. Проверь
   восстановление на копии. Не используй migrate reset, db push --force-reset,
   --accept-data-loss и другие команды, допускающие потерю данных.
6. Не коммить .env, ключи, БД, личную анкету и пользовательские медиа.
   Для проверок используй вымышленные примеры и временную БД.
7. Обычные операции не вызывают ИИ: просмотр, поиск, сохранение, статусы,
   переключение дублей, ручная правка, анкета, версии и экспорт.
8. Число дублей и итераций не ограничивай бизнес-правилом. Это не отменяет
   технических лимитов размера файла и ограниченных повторов сетевого запроса.
9. Сервер проверяет входные данные и принадлежность связанных записей.
   Технический повтор задачи не создаёт новый дубль.
10. Проверки запускай по конкретным рискам этапа. Не делай платные вызовы
    модели без необходимости: сетевые операции в автопроверках подменяй.
    Не называй неисполненную проверку пройденной.
11. Обнови docs/IMPLEMENTATION_STATUS.md и подготовь отчёт
    `docs/reviews/STAGE_09.md` по REVIEW_TEMPLATE.md.
12. Сделай коммит этапа и отправь рабочую ветку в GitHub, если доступ настроен.
    Не делай force push и не сливай в main автоматически.
13. Остановись до внешней проверки. Следующий этап начинается после принятия
    текущего или исправления блокирующих замечаний.

Это личное приложение для одного автора. Работа через localhost не требует
системы аккаунтов. Не открывай приложение наружу в этом этапе.

## Что входит

1. Запусти `npm run build` и исправь **новые** ошибки сборки. Исходные ошибки
   проекта (`src/lib/analyze.ts`, `scripts/score-analyz.ts` и уже известные
   typecheck) отделяй от ошибок этапа. Не раздувай правки старого скоринга,
   если сборка падает только из‑за них: либо точечно исключи скрипт из
   production build, либо исправь минимум, чтобы `next build` проходил.
2. Проверь миграции на **чистой** SQLite и на **существующей** базе
   (обычный `migrate deploy`, без reset и force-reset). Сравни сохранность
   payload и пользовательских данных с резервной копией.
3. Ручной браузерный smoke-тест на localhost (Windows). Зафиксируй в отчёте
   URL, что нажал, что увидел. Одна статичная картинка экрана не считается
   проверкой. Пройди:
   - создание идеи;
   - создание нескольких дублей;
   - загрузка и просмотр медиа;
   - расшифровка;
   - вопросы и ответы;
   - создание сценария;
   - несколько версий сценария;
   - сравнение дублей;
   - выбор финального дубля и сценария;
   - экспорт и backup.
4. Проверь ошибки UI:
   - пустые состояния;
   - повторное нажатие кнопок;
   - конфликт устаревшей версии;
   - ошибка Groq (ключ отсутствует или mock/невалидный ответ, без платного
     вызова без необходимости);
   - длинные тексты;
   - отсутствие медиа.
5. Исправляй **только найденные MVP-блокеры**. Не добавляй новых продуктовых
   возможностей.
6. Обнови `README.md` и `docs/reviews/STAGE_09.md`.
7. Добавь smoke-тесты только там, где ошибка была обнаружена.

## Что не входит

Не делай в этом этапе:

- аккаунты и авторизацию;
- публикацию в интернет;
- новый AI-функционал;
- мобильное приложение;
- аналитику просмотров;
- автоматический выбор лучшего дубля.

Запись с камеры и микрофона в браузере по-прежнему не входит.

## Порядок работы по файлам

Пути предполагаемые: меняй только то, что нужно для блокеров и отчёта.

### 1. Сборка

`package.json`, конфиг Next/TypeScript — только если `npm run build` падает
из‑за кода этапа или из‑за попадания служебных скриптов в компиляцию.

### 2. Миграции

Существующие `prisma/migrations/*`. Новую миграцию добавляй только если
блокеру нужна схема. Сначала резервная копия.

### 3. UI и API найденных блокеров

Только файлы, где проверка сломалась.

### 4. Тесты

Новые или расширенные тесты — регрессия по найденной ошибке. Не пиши
отдельный большой набор «на всякий случай».

### 5. Документация

`README.md` — как запустить, что проверено вручную, ограничения.
`docs/IMPLEMENTATION_STATUS.md` — этап 8 принят на базовом SHA; этап 9
на ревью.
`docs/reviews/STAGE_09.md` — отчёт: build, миграции, браузерный smoke,
непроверенное отдельно.
