# 08. Скрытие и перенаправление старых пользовательских маршрутов

## 1. Назначение и границы

Убрать из user path только legacy screens, чьё полезное поведение уже покрыто новым flow, сохранив deep links и data.

## 2. Предварительные условия и зависимости

- P01–P12 применимые части приняты.
- Baseline содержит legacy routes и useful actions.
- Для каждого кандидата есть matrix: action, save, error, return, new equivalent.

## 3. Точные результаты

- Parity matrix с доказательствами/tests для каждого route.
- Legacy user links удалены только после parity.
- Redirect map сохраняет thought id и допустимый context/query; no loops/404.
- Bookmarks/deep links получают предсказуемый redirect/not-found.
- Мёртвый UI удаляется только если server/API/shared behavior не нужен.
- Rollback map перечисляет точки входа.

## 4. Не входит в этап

- Удаление API, таблиц, данных, admin/internal routes.
- New features и visual polish.
- Mass URL rename без product decision.
- Redirect до parity.

## 5. Критерии приёмки и проверки

- Для каждого hidden route покрыты useful action + save + error + return.
- Redirect сохраняет id, data и не loop.
- Global nav показывает только «Мысли / Профиль».
- Direct legacy links и browser back протестированы.
- Backend/shared modules не удалены только из-за старого UI import.
- Не затронуты неинвентаризированные admin/system routes.

## 6. Риски и известные ограничения

- Неизвестные deep links: при отсутствии telemetry предпочесть redirect, не hard delete.
- Server/client redirect semantics различаются.
- Legacy component может быть единственным владельцем mutation; сначала reuse/extract.

## 7. Промпт для Cursor

> Результат этапа проходит проверку у агента «Создание приложение» перед следующим шагом.


```text
В src/ выполни только этап скрытия/redirect legacy user routes.

Сначала исследуй router, navigation, middleware/rewrites, legacy routes из baseline, их actions/mutations/error/return, imports и route tests. Прочитай START_HERE.md, SOURCE_OF_TRUTH_2026-09-15.md и DEVELOPMENT_READINESS_2026-09-15.md. Сопоставь каждый route с принятыми P01–P12.

До кода составь parity matrix: old route → useful action → save → error → return → new equivalent → evidence. Не hide/redirect, если любой пункт не покрыт. Для покрытых routes убери user entry points и добавь minimal redirects с thought id/context/query, проверив loops и back. Admin/internal routes без baseline evidence не трогай.

Удаляй только proven dead UI. API/models/tables/data/shared behavior не удаляй. Новые функции и restyle не добавляй.

Добавь route tests для redirects, deep link/id/query, 404 и loop prevention. Запусти existing tests/lint/typecheck/build из package.json/docs; scripts не выдумывай. Pre-existing blockers отдельно.

Не commit/push без команды. Handoff: parity matrix, redirect map, removed files/entry points, checks, blockers, rollback. Не переходи к R1–R8; жди review.
```

## 8. Условие остановки

После проверенных redirects остановиться; hardening не начинать автоматически.

После выполнения этапа передай результат в чат агента **«Создание приложение»** (Grok Bot). Не начинай следующий этап до вердикта: принято / правки / стоп.
