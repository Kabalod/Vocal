# 07. P10–P12: профиль

## 1. Назначение и границы

Реализовать active portrait, questionnaire/amend по одному вопросу и явное подтверждение нового портрета. Профиль помогает AI, но не блокирует создание мысли.

## 2. Предварительные условия и зависимости

- P00 shell принят; `/profile` известен.
- Изучены P10–P12 prototypes и active/draft profile models/endpoints.
- Подтверждено, где AI читает active portrait.

## 3. Точные результаты

- `/profile` показывает real active portrait или honest empty.
- Questionnaire/amend — один вопрос за раз; text/voice ответы message semantics, не take.
- Draft/progress сохраняются по contract и восстанавливаются reload.
- Preview нового portrait отделён от active.
- Только explicit confirm активирует; cancel/unfinished amend оставляет старый active для AI.
- Loading/error/retry/save/confirm и duplicate-confirm protection.
- Thought creation и studio не получают profile guard.

## 4. Не входит в этап

- Registration, account settings, payments, teams.
- Auto-apply draft.
- Takes/media.
- Restyle других routes.

## 5. Критерии приёмки и проверки

- Active/draft различимы в data/UI.
- Unfinished amend после reload/cancel не меняет active/AI context.
- Confirm атомарно активирует version; повтор не создаёт extra active versions.
- Voice questionnaire reply не появляется в takes.
- Thought создаётся при empty/incomplete profile.
- Save/confirm error не теряет answer и не показывает false success.

## 6. Риски и известные ограничения

- Mutable profile field может потребовать backwards-compatible draft/active schema.
- AI context cache переключается только после confirm.
- Async transcription может ограничить момент confirm по contract.

После profile lifecycle остановиться; старые routes пока не скрывать.
