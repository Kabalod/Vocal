# 02. P01: архив мыслей, календарь и быстрые переходы

Статус: прежняя функциональная основа P01 принята 16 сентября 2026 года. Ниже описана новая ревизия P01.1–P01.5; она ещё не реализована и не отменяет принятую историю этапа.

## 1. Назначение и границы

Заменить `/reels` на архив полароидов с реальными данными, cursor pagination, поиском, автоматическими статусами, календарём и разными быстрыми переходами в preview и диалог.

Канон экрана: `docs/design/references-new/09_thoughts_archive/`. Он заменяет прежнюю композицию `03_thoughts_list`, но не меняет общие токены soft violet и продуктовые правила статусов.

В этап не входят новая мысль P02, изменение логики студии, редизайн диалога/сценария, генерация уникальных изображений моделью, избранное и ручное изменение статуса.

## 2. Что уже есть в коде

- `listReels()` поддерживает поиск, status, sort, limit и cursor pagination.
- `/api/reels` возвращает страницу карточек и следующий cursor.
- `ReelList` уже умеет загружать следующую страницу, но использует кнопку, локальные фильтры и старую композицию.
- Статусы нормализуются через один boundary.
- Для календаря нет отдельного контракта доступности дней/месяцев.
- Текущий preview загружает карточку и сценарии отдельно; нужно переиспользовать данные и не создавать N+1 запрос на каждую плитку.

## 3. Контракт поведения

### 3.1 Общие фильтры

- Поиск, статус и диапазон дат действуют совместно (`AND`).
- Фильтры отражены в URL, чтобы refresh/back и переход desktop ↔ mobile сохраняли состояние.
- Новый фильтр отменяет устаревший запрос, очищает cursor и начинает выдачу с первой страницы.
- Пустой результат поиска/фильтра отличается от полностью пустого архива.
- Фильтр не меняет статус мысли и не вызывает модель.

### 3.2 Календарь

- Доступны два режима: конкретный день и весь месяц.
- Дни с мыслями подсвечиваются по полному набору совпадений, а не по уже загруженным карточкам.
- Для этого нужен компактный calendar-facet контракт: месяц, список дней с количеством мыслей и границы доступных данных. Не загружать все карточки ради точек календаря.
- Выбранный день визуально отличается от дня, в котором просто есть мысли.
- Выбор месяца имеет явное действие «Показать месяц» либо эквивалентную доступную кнопку; обычный переход стрелками к соседнему месяцу только меняет вид календаря и не должен неожиданно перезагружать архив.
- Есть явный сброс даты.
- Диапазон строится в локальной календарной зоне пользователя и передаётся серверу как однозначные границы `[from, to)`, чтобы не терять мысли около полуночи.
- До ответа пользователя базой считается `createdAt`. Не использовать `updatedAt` молча.

### 3.3 Lazy loading

- По умолчанию новые мысли раньше старых; одинаковые даты стабилизируются `id`.
- Следующая страница загружается через `IntersectionObserver` при приближении к концу списка.
- Одновременно выполняется только один запрос следующей страницы.
- Повторный cursor и повторные ids не добавляют дубликаты.
- Во время загрузки уже показанные карточки остаются на месте; внизу виден компактный progress.
- Ошибка первой страницы заменяет содержимое error-state; ошибка следующей страницы показывает локальный retry внизу.
- После конца данных observer отключается.
- Предусмотреть доступный fallback «Загрузить ещё», если observer недоступен или пользователь управляет страницей без ожидаемой прокрутки.

### 3.4 Карточка desktop

- Визуально — вертикальный полароид около `3:4`, адаптивная сетка.
- `i` — отдельная кнопка предварительного просмотра.
- Статус — отдельная неинтерактивная иконка с доступным текстовым названием.
- Нижнее поле со стрелкой не имеет отдельной обводки. Оно является заметной частью общей карточки.
- Клик по карточке вне `i`, включая стрелку, открывает `/reels/[id]` сразу на рабочем диалоге с последним принятым сценарием и последним доступным материалом.
- Hover: небольшой `translateY`/наклон, усиление тени и контраста. Не использовать циклическую вибрацию. Не менять размер шрифта и геометрию текста так, чтобы сетка прыгала.
- Focus-visible даёт столь же понятное состояние, как hover. `prefers-reduced-motion` отключает перемещение.

### 3.5 Карточка mobile

- Сетка вертикальных карточек `3:4`; целевой экран 390×844, дополнительно 360×800 и 430×932.
- Верхняя содержательная область открывает preview.
- Нижняя полоса со стрелкой открывает диалог.
- На mobile нет hover, наклонов, вибрации и автодвижения.
- Верхняя и нижняя области — отдельные semantic controls с зонами нажатия не меньше 44×44 px; вложенные клики не всплывают друг в друга.
- Календарь по нажатию на дату открывается bottom sheet — рекомендуемое решение до подтверждения пользователя.

### 3.6 Preview и вход в работу

Preview показывает название, статус, последний принятый сценарий, номер версии, количество дублей и две команды:

- «Снять новый дубль»;
- «Перейти к работе с мыслью».

Preview не создаёт AI-вызов и не меняет рабочий контекст.

Быстрый вход открывает вкладку «Диалог». Если сценария нет, диалог открывается по исходной мысли, последнему дублю и истории. Если последняя версия ещё обрабатывается, показывается честный статус; более старый готовый сценарий не называется последним результатом обработки.

Back возвращает в архив с теми же фильтрами и разумно восстановленной позицией. Точное восстановление DOM всех бесконечных страниц не является обязательным, если выбранная карточка и фильтры восстанавливаются без скачка к неверному набору.

## 4. Решения, которые ещё нужно подтвердить

Перед подключением API календаря пользователь подтверждает:

1. Дата календаря — `createdAt` (рекомендация) или `updatedAt`.
2. Mobile-календарь — bottom sheet по нажатию на дату (рекомендация) или другое размещение.
3. Быстрый вход без сценария — диалог по доступным материалам (рекомендация) либо обязательный preview.

До ответа Cursor может строить компоненты и тесты вокруг явных параметров, но не должен необратимо мигрировать данные. Временно использовать рекомендованные значения как документированные defaults.

## 6. Итоговая приёмка P01

- Реальные данные, без demo-массива и AI-вызовов при просмотре.
- Day/month filters находят мысли, включая ещё не подгруженные страницы.
- Search/status/date дают один предсказуемый набор; refresh/back сохраняют его.
- Lazy loading не дублирует и не теряет элементы, ошибки локализованы.
- Desktop: `i` preview, остальная карточка/стрелка — диалог; hover не вызывает reflow.
- Mobile: верх preview, низ диалог; никакой hover animation.
- Без сценария быстрый вход не тупиковый.
- Три пользовательских статуса; никаких ручных status dropdown.
- Keyboard, screen reader labels, reduced motion и целевые ширины проверены.
- Скриншоты desktop и mobile приложены к handoff.

## 7. Риски

- Calendar facets без отдельного запроса будут лгать при lazy loading.
- `updatedAt` меняет календарное положение после любого редактирования; поэтому default — `createdAt`.
- Увеличение текста на hover вызовет layout shift; использовать transform/weight/contrast без изменения метрик.
- Три колонки на 360 px могут не выдержать длинные русские заголовки и 44 px action zone. Если ручная проверка не проходит, сохранить `3:4`, но перейти на две колонки на узкой ширине; это адаптивная защита, не смена стиля.
- Preview не должен тянуть полные сценарии для каждой карточки заранее. Загружать детали по открытию либо вернуть только компактный summary.
