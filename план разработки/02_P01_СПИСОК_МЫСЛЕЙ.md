# 02. P01: список мыслей

## 1. Назначение и границы

Заменить только основное представление `/reels` на рабочий список мыслей, сохранив источники данных и действия. Список — вход в путь, не декоративная галерея.

## 2. Предварительные условия и зависимости

- P00 принят; shell и primitives доступны.
- На этапе 00 установлены реальные endpoint/query/model и status semantics.
- Согласован переход элемента в `/reels/[id]` или временный безопасный route.

## 3. Точные результаты

- `/reels` загружает реальные мысли через существующий data layer.
- Элемент показывает узнаваемую мысль и ровно один статус: «Не завершена», «В работе», «Успешно завершена».
- Loading, empty, error+retry и loaded states.
- Доступное create action, ведущее в P02 без требования профиля.
- Открытие сохраняет корректный id и back/return behavior.
- Legacy statuses нормализуются в одном boundary либо блокируют релиз; UI не изобретает подписи.

## 4. Не входит в этап

- Форма/mutation создания (этап 03).
- Studio, path/polaroid, recording, profile.
- Изменение backend contract без необходимости.
- Финальная художественная полировка.

## 5. Критерии приёмки и проверки

- Нет demo-массива; список отражает refresh/reload.
- Empty имеет действие; error не маскируется под empty и имеет retry.
- Статусы ограничены тремя строками.
- Item доступен keyboard, имеет однозначный переход, long text не ломает layout.
- Create доступен без профиля и не получает искусственный guard.
- Existing unit/integration/e2e и build не имеют новых failures.

## 6. Риски и известные ограничения

- Backend может иметь больше statuses; mapping согласовать с source-of-truth.
- Legacy delete/archive/filter не переносить автоматически, но отметить полезное behavior.
- Pagination/cache следуют существующей реализации, не выдумываются.
