# 09. R1–R8 + P13–P16: надёжность, голос, медиа, контекст и экспорт

## 1. Назначение и границы

Укрепить принятый путь после функционального parity. Работать последовательными R1–R8 с отдельным checkpoint; смысл P13–P16 сначала сверить с каноном, не угадывать по названию.

## 2. Предварительные условия и зависимости

- Этапы 02–08 приняты или exceptions явно записаны.
- Есть baseline tests, schema, media state machine и список providers.
- P13–P16 сопоставлены с R-подфазами по `SOURCE_OF_TRUTH`/`DEVELOPMENT_READINESS`.

Порядок:

1. **R1 — contracts/data:** schema/API invariants, independent finals, active/draft profile.
2. **R2 — idempotency/races:** double submit, retry, stale responses, concurrent tabs.
3. **R3 — errors/recovery:** actionable errors, reload/reconnect, processing recovery.
4. **R4 — voice reliability:** permission/transcription/cancel/retry; message ≠ take.
5. **R5 — take/media:** limits/formats, cleanup, job timeout, scriptless regression.
6. **R6 — AI context:** only confirmed profile, current thought/script, no cross-thought leakage.
7. **R7 — P16 export:** only canonical format/channel; agreed materials and errors.
8. **R8 — a11y/privacy/observability:** keyboard/focus/labels, safe logs/metrics, regression suite.

R4 depends R1–R3; R5 R1–R3; R6 R1/profile; R7 R1/R5/R6; R8 all previous.

## 3. Точные результаты

- Mapping P13–P16 ↔ R1–R8 with canonical references.
- Each subphase has small diff, tests/evidence, existing checks, rollback note.
- Verified invariants: three statuses; explicit record start; voice message ≠ take; independent finals; active profile only after confirm; scriptless recording.
- Recovery after refresh/offline/retry where supported; no eternal pending/processing.
- AI context isolates thoughts and uses confirmed active profile only.
- P16 export only as canon specifies: composition, name/type, pending/error/retry; no secrets in artefact/log.
- Observability without personal thought/audio/profile content in logs.
- Regression tests for critical transitions and a11y/responsive smoke.

## 4. Не входит в этап

- New features/channels/embedded camera.
- Pixel-perfect polish (stage 10).
- Arbitrary architecture/provider/test framework replacement.
- Unconfirmed export.

## 5. Критерии приёмки и проверки

- Each R subphase ends separately and does not start next before review.
- Repeat operation creates no duplicate thought/message/take/profile activation/export.
- Stale response cannot overwrite newer confirmed state.
- Voice errors do not create takes; media retry preserves scriptless flow.
- Reconnect/reload shows server state or recovery.
- AI receives only current thought + active confirmed profile.
- Logs/errors contain no raw media/full personal content/secrets.
- Existing checks and regression suite pass; pre-existing blockers separate.

## 6. Риски и известные ограничения

- Exact P13–P16 meaning comes from docs; this file sets hardening process, not new contract.
- Idempotency may need server keys/migration; backwards compatible.
- External providers may be unavailable; use contract tests and honest manual protocol.
- Observability must not collect user content.

## 8. Условие остановки

После каждой R-подфазы обязательна остановка. Этап завершён только после восьми reviews.

### Проверка агентом

После выполнения этапа передай результат в чат агента **«Создание приложение»** (Grok Bot). Не начинай следующий этап до вердикта: принято / правки / стоп.

## После каждого принятого R
