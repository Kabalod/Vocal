# 03. P02: новая мысль

## 1. Назначение и границы

Реализовать короткий устойчивый путь создания мысли с реальным сохранением и переходом к сущности. Профиль не является предварительным условием.

## 2. Предварительные условия и зависимости

- P01 принят и имеет entry point.
- Найдены create mutation, validation, response и cache invalidation.
- Понятен target route после success.

## 3. Точные результаты

- Доступная форма ввода исходной мысли с каноническими labels.
- Client validation только по подтверждённому contract; server error отдельно.
- Защита от повторной отправки, pending и восстановление после ошибки.
- Реальный API create, корректный id, начальный статус «Не завершена», обновление списка и переход в `/reels/[id]`.
- Cancel/back не создаёт запись и возвращает к списку.
- Empty/incomplete profile не блокирует create.

## 4. Не входит в этап

- Автоматический dialogue/recording после create.
- Profile, script generation, upload/record.
- Draft autosave, если его нет в каноне.
- Новые поля «на будущее».

## 5. Критерии приёмки и проверки

- Одна отправка создаёт ровно одну мысль при double-click/slow network.
- При API error ввод не теряется, retry доступен.
- После success list и deep link согласованы после reload.
- Новый объект имеет канонический status; create не зависит от profile completeness.
- Back/cancel не оставляют ложную сущность.
- Tests/lint/build без новых failures.

## 6. Риски и известные ограничения

- API может создавать object до первого AI response; не объединять операции без idempotency.
- Cache invalidation зависит от текущего data layer.
- При несовпадении initial backend status нужен boundary mapping, не смена UI copy.

## 7. Промпт для Cursor

> Результат этапа проходит проверку у агента «Создание приложение» перед следующим шагом.


```text
В src/ выполни только P02 — создание новой мысли.

Сначала исследуй route/component, реальную mutation/API, model/validation, cache invalidation, duplicate submit и tests. Прочитай START_HERE.md, SOURCE_OF_TRUTH_2026-09-15.md, THOUGHT_JOURNEY_REVISION_2026-09-15.md, DEVELOPMENT_READINESS_2026-09-15.md. Сверь P01 переходы; API не выдумывай.

Реализуй узкий E2E create flow: ввод, доступная validation, pending, double-submit guard, server error без потери текста, retry, cancel/back, success на /reels/[id] с реальным id. Update/invalidate list принятым способом. Initial visible status — «Не завершена». Create ОБЯЗАТЕЛЬНО доступен без заполненного профиля: убери только artificial guard, не ломай auth/security.

Не запускай AI dialogue/recording автоматически. Не добавляй fields, autosave, profile, script/media. Сохраняй backend/API logic и P00 components.

Запусти существующие repository scripts для tests/lint/typecheck/build после просмотра package.json; scripts не выдумывай. Тесты: success, server error/retry, duplicate submit, missing profile. Проверь reload list и back/cancel. Pre-existing blockers отдельно.

Не commit/push без просьбы. Handoff: files, persistence/cache, checks, blockers, rollback. Не переходи к studio; жди review.
```

## 8. Условие остановки

После доказанного create/save/return остановиться и дождаться проверки.

### Проверка агентом

После выполнения этапа передай результат в чат агента **«Создание приложение»** (Grok Bot). Не начинай следующий этап до вердикта: принято / правки / стоп.
