# 00. Подготовка: соглашения и исходная точка

## 1. Назначение и границы

Создать проверяемую карту текущего продукта до изменения UI: маршруты, состояния, API/данные, тестовые команды, расхождения и порядок источников истины. Этап только исследовательский и документирующий.

## 2. Предварительные условия и зависимости

- Доступны канонические документы из `C:/Users/Благости/Desktop/План/Vocal_design_plan_2026-09-15/`.
- Cursor открыт в `src/`.
- Известен безопасный способ запустить текущий продукт или зафиксирована причина невозможности.

## 3. Точные результаты

- Baseline-документ в принятом в repo месте (предпочтительно существующий `docs/`).
- Таблица текущих/целевых routes: `/reels`, create thought, `/reels/[id]`, `/profile`, legacy user paths.
- Карта сущностей: мысль, сообщения/предложения, версии сценария, дубль, final take, final script, active/draft profile.
- Список реальных scripts из `package.json`, package manager, test environment и baseline failures.
- Матрица правило → текущая реализация → этап исправления, включая `SCRIPT_REQUIRED`.
- Rollback-подход для кода и возможных миграций.

## 4. Не входит в этап

- Изменение UI, API, схемы БД или зависимостей.
- Исправление найденных дефектов.
- Коммиты, push, deploy.

## 5. Критерии приёмки и проверки

- Каждое неподвижное правило из `README.md` отражено в матрице.
- Ни один route/API/script не выдуман: у каждого есть ссылка на файл repo.
- Подтверждённые факты, предположения и вопросы разделены.
- Выполнен доступный baseline запуск существующих test/lint/build scripts либо записаны точные blockers.
- Рабочее дерево не изменено, кроме согласованного baseline-документа.

## 6. Риски и известные ограничения

- Имена P/R могут не совпадать с компонентами; ориентироваться на поведение и канон.
- Старые routes могут содержать полезные скрытые операции; визуально старое не равно бесполезному.
- Тесты могут требовать secrets/services; не раскрывать секреты и не подменять реальные интеграции fake success.
