# План разработки лендинга Vocal

## 1. Цель и границы

Донести путь: своя мысль → уточняющий диалог → основа разговорного ролика → запись → понятная обратная связь. Основная конверсия — переход к подготовке первой мысли в существующем приложении.

Делаем один адаптивный лендинг с общими компонентами и данными, а не две независимые страницы. Desktop шире раскрывает пользу, mobile сохраняет уже выбранную короткую композицию. Дополнительные desktop-секции не добавлять в мобильную последовательность автоматически. Можно реализовать их общей разметкой с видимостью на desktop; не дублировать hero, video и текст для разных ширин.

Не входит: переделка приложения, регистрация с нуля, платежи, изменения моделей данных, производство настоящего видео, публикация production. Репозиторий в рамках подготовки этого плана не проверялся: пути файлов и названия компонентов ниже предлагаемые, точные маршруты определяются в L00.

## 2. Источники и структура

| Блок | Mobile <768 px | Tablet 768–1023 px | Desktop ≥1024 px |
|---|---|---|---|
| Header | Vocal и Войти | То же | Лого, якоря, Войти |
| Hero | Заголовок, видео, текст, CTA | Мобильный порядок с ограниченной шириной | Слева заголовок/текст/CTA, справа видео |
| Преимущества | 3 вертикальные строки | 3 строки или колонки при достаточной ширине | 3 колонки |
| Диалог | Заголовок и переписка | Одноколоночный | Пояснение слева, диалог справа |
| Результат | Не показывать в этой итерации | Не показывать | Пример слева, пояснение справа |
| Обратная связь | Не показывать в этой итерации | Не показывать | Пояснение слева, разбор справа |
| FAQ | Не показывать в этой итерации | Не показывать | Заголовок слева, аккордеон справа |
| Финальный CTA | Вертикально | Вертикально | Горизонтальный баннер |

Это явное решение для согласования двух разных макетов. Расширение мобильной страницы дополнительными секциями — отдельное изменение после просмотра реализации.

## 3. Тексты и содержание

### Hero

- H1: «Мысль уже есть. Давайте найдём для неё слова.»
- Mobile описание: «Vocal поможет раскрыть мысль в диалоге, собрать основу ролика и понять, что улучшить в записи.»
- Desktop описание: «Раскройте мысль в диалоге, подготовьте основу ролика и получите обратную связь по записи.»
- Все главные CTA: «Подготовить первый ролик».
- Подсказка: «Начните с мысли — текстом или голосом».
- Подпись полароида: «От моей мысли до записи».

### Преимущества

Mobile: «Диалог с ИИ для ясных мыслей» / «Вопросы, которые помогают раскрыть мысль»; «Сценарий под ваш стиль» / «Сохраните свои слова и интонацию»; «Запись и обратная связь» / «Понятные рекомендации для следующего дубля».

Desktop: «Проясните мысль», «Сохраните свой стиль», «Поймите, что улучшить» с теми же пояснениями. Не обещать техническую персонализацию, которая ещё не реализована.

### Пример переписки

Единый набор из 6 сообщений на обеих ширинах; desktop PNG показывает сокращённый пример, число пузырей не является обязательной геометрией.

1. Пользователь: «Хочу снимать, но всё время откладываю.»
2. Агент: «Что останавливает перед записью?»
3. Пользователь: «Кажется, что сначала нужно ещё поучиться.»
4. Агент: «Был случай, когда вы выбрали обучение вместо записи?»
5. Пользователь: «Купил третий курс по съёмке, хотя ещё не записал ни одного ролика.»
6. Агент: «Попробуйте начать с этого случая. Что вы тогда поняли?»

Агент всегда слева: фиолетовый пузырь, иконка слева. Пользователь всегда справа: серый пузырь, аватар справа. Порядок сообщений хронологический в DOM. Подпись «Пример диалога». Это статическая демонстрация, не работающий чат и не форма отправки.

Mobile заголовок: «Начните с разговора». Desktop: «От общей идеи — к вашей истории». Desktop пояснение: «Vocal задаёт вопросы, чтобы найти конкретный случай и главное, что вы хотите сказать». «Мысль · Уточнение · Основа ролика» — статические этапы, не интерактивные табы.

### Desktop: результат, разбор, FAQ

Результат: заголовок «В основе — ваш опыт». Текст: «Соберите понятное начало, основную мысль и завершение. Сохраните свои слова и интонацию». Карточка «Начало ролика»: «Я купил третий курс по съёмке. Но так и не записал ни одного ролика». Маркер «Иллюстративный пример».

Разбор: «Записали дубль? Найдите следующий шаг». Пояснение: «Посмотрите, что получилось и что стоит уточнить перед новой записью». Карточка «Пример обратной связи»: «Что получилось — Личный случай сразу раскрывает тему»; «Что попробовать — Поясните, почему снова выбрали обучение вместо записи». Не добавлять баллы.

FAQ: «Перед первой записью». Вопросы: «Можно начать без сценария?», «Обязательно сразу записывать видео?», «Как обрабатываются мои записи?». Первые два ответа сформулировать по подтверждённому сценарию приложения. Третий — только по фактической политике и реализации; черновое неизвестное утверждение не публиковать. Отсутствие утверждённого ответа отметить как блокер выпуска, но не останавливать вёрстку остальных блоков.

Финальный заголовок: «Начните с того, что хочется сказать». Повтор основного CTA.

## 4. Дизайн и адаптация

Сначала переиспользовать действующие токены Vocal. Если нужных нет, добавить локальные landing-токены: фон около #18191C, поверхность #24242B, основной текст #F4F2F6, вторичный #B9B6C3, акцент #AA8BEF, кнопка #7751F5. Это стартовые значения: проверить контраст в реальной вёрстке. Засечки только для основных заголовков; основной текст и контролы — sans. Использовать шрифты с кириллицей, проверить computed font-family и загрузку. Не подменять отсутствующий display-шрифт случайным системным serif.

- Desktop контейнер до 1200 px, поля 32–48 px, межколоночный gap 48–64 px. На 1920+ контейнер ограничен, контент не растягивается бесконечно.
- Mobile поля 20 px (на 360 допустимо 16), body 16–18 px, подписи от 14 px. Заголовок примерно 36–44 px; desktop 52–64 px. Точные размеры уточнить по переносу текста.
- Вертикальные интервалы секций: mobile 40–56 px, desktop 64–88 px. Кнопки 48–56 px высотой; зоны нажатия не менее 44×44 px.
- Hero на desktop — CSS grid с отдельными областями title, video, copy, action. DOM-порядок соответствует mobile: title/video/copy/action. Менять расположение CSS, не дублировать видео.
- Преимущества: flex/grid, иконки 24–32 px, тонкие разделители. Не использовать картинки с текстом.
- Полароид: холодная светлая бумага, умеренные поля, более широкая нижняя подпись, контактная и мягкая внешняя тени. Наклон 1–2°, на воспроизведении выровнять. Поворот не должен обрезать края или давать overflow.
- Фактура мелкая и слабоконтрастная. Не растягивать PNG всего макета на фон. При отсутствии исходной текстуры достаточно спокойного однотонного фона до добавления ассета.
- Пузырь чата mobile до 82–86% доступной строки с учётом аватара, desktop до 78%. Длинные слова переносятся, аватары не сжимаются. Никакого внутреннего скролла в демонстрации.
- Не копировать высоту/масштаб текста из уменьшенного PNG буквально. При 200% увеличении страницы содержимое остаётся доступным.

## 5. Последовательность разработки

### L00 — аудит и фиксация базы

Прочитать правила репозитория; записать текущую ветку/SHA, git status, стек, package scripts. Найти публичный маршрут лендинга, существующие вход/регистрацию/создание мысли и поведение авторизованного пользователя. Если корень занят архивом, не переносить его без решения: подготовить лендинг на отдельном preview-маршруте и описать интеграцию. Создать `docs/landing/IMPLEMENTATION_REPORT.md` с результатами. Проверить действующие проверки до правок и отделить исходные ошибки от новых.

Готово: найдены реальные точки интеграции, определён scope файлов, пользовательские изменения сохранены. Коммит: docs(landing): capture baseline and implementation scope.

### L01 — компоненты, данные и ассеты

Создать локальные токены/стили и общую модель content. Предлагаемые компоненты: LandingHeader, LandingHero, PolaroidVideo, Benefits, ConversationDemo, ResultExample, FeedbackExample, LandingFaq, FinalCta, LandingFooter. Не навязывать эти пути, если в проекте иная структура.

Полные PNG из mockups — только reference-файлы в docs. Не отдавать их как фон готовой страницы. Фото из концепта — временная иллюстрация; допустимо подготовить отдельно обрезанный постер, пометив его demo. Итоговое фото/видео автора должно заменяться через media config. Настоящего видео в комплекте нет: не подставлять случайный ролик. Иконки из существующего набора. Медиа с фиксированными размерами/aspect-ratio.

Готово: общие компоненты/контент не задублированы, референсы отделены от production-ассетов. Коммит: feat(landing): add shared components and content.

### L02 — мобильная версия

Собрать точную последовательность mobile, начиная с 390 px; проверить 360 и 393. Реализовать полароид, CTA, вертикальные преимущества и сообщения с правильными сторонами. Не добавлять бургер при двух элементах в шапке. Не приклеивать CTA поверх содержимого в этой итерации.

Готово: все блоки читаемы, нет обрезанных краёв, скролл только страницы. Коммит: feat(landing): implement mobile layout.

### L03 — desktop и tablet

При ≥1024 px перестроить hero в две колонки, преимущества в три. Добавить секции desktop согласно таблице. Диалог с пояснением занимает две колонки; результат — противоположная композиция; FAQ и closing CTA — широкие блоки. 768–1023 оставляет мобильную последовательность, контейнер около 680 px. Якорные ссылки показывать только к видимым секциям, с scroll-margin для header.

Готово: desktop не выглядит растянутой колонкой mobile; диапазон 1024–1280 не тесный, 1920 не растянут. Коммит: feat(landing): build desktop sales sections.

### L04 — действия и состояния

Связать Войти и CTA с маршрутами из L00. Для гостя использовать существующий auth-flow с безопасным returnTo; для вошедшего — существующее создание/подготовку мысли. Не создавать записи автоматически при каждом рендере лендинга; использовать действующий продуктовый сценарий. Не добавлять auth заново.

Video: без autoplay со звуком; playsInline, controls, captions при наличии дорожки, preload=none/metadata. Play через клавиатуру и pointer. До предоставления media src показать честное состояние «Видео готовится» вместо работающего на вид ложного play; это допустимо для preview, блокер финального выпуска. Ошибка загрузки показывает сообщение и повтор, не пустую рамку. При открытии в modal нужны Escape, focus trap/restore; предпочтительно inline-плеер.

FAQ — details/summary либо существующий доступный accordion; Enter/Space, корректные expanded states. Якоря работают без JS по возможности. Static chat не принимает ввод, не вызывает AI и не обещает live-сессию.

Готово: нет href=# в CTA, фиктивных кликов и вложенных кнопок. Коммит: feat(landing): connect actions and accessible states.

### L05 — качество, производительность, SEO

Один H1, последовательные H2, lang=ru, page title/description, корректные alt. Canonical и OG URL брать из реального домена, не выдумывать. Черновой preview не индексировать. Контраст текста минимум 4.5:1 для обычного текста, видимый focus. prefers-reduced-motion отключает необязательные анимации; чат можно оставить статичным. Не применять бесконечный shimmer/typing.

Не загружать полный ролик до взаимодействия, подготовить оптимизированный poster; изображения ниже fold lazy. Шрифты кириллица без layout shift, текстуры оптимизированы. Сохранить семантический текст в HTML. Проверить Lighthouse на production build, записать условия измерения; рекомендации по LCP ≤2.5s и CLS ≤0.1 — цели, не обещание полевых метрик. Если аналитика уже есть: landing_cta_click с placement, video_start, faq_open без текста мыслей/PII. Новый внешний трекер не добавлять.

Готово: отсутствуют новые ошибки console/hydration и тяжёлая загрузка видео при открытии. Коммит: perf(landing): polish accessibility and loading.

### L06 — функциональная и визуальная проверка

Запустить реальные lint/typecheck/build/test команды проекта. Не создавать тесты, которые только проверяют наличие CSS-классов. Значимые проверки: гостевой/авторизованный CTA, сохранение returnTo, FAQ keyboard, video missing/error, mobile порядок, роли/стороны сообщений, отсутствие overflow.

| Viewport | Артефакт |
|---|---|
| 360×800 | mobile full-page |
| 390×844 | mobile full-page + первый экран |
| 393×852 | mobile full-page |
| 768×1024 | tablet |
| 1024×768 | переход к desktop |
| 1280×800 | desktop full-page |
| 1440×900 | desktop full-page + первый экран |
| 1920×1080 | wide desktop |

Дополнительно: открытый FAQ, keyboard focus, состояние без видео и playback при наличии файла. Проверить Chromium и WebKit; если реальный Safari iPhone не проверялся, прямо написать это. Проверка scrollWidth сама по себе недостаточна: убедиться визуально, что overflow:hidden не прячет края. Сравнивать PNG с референсом по композиции, а не требовать побайтового совпадения генеративной картинки.

Готово: скриншоты текущего build в `docs/landing/review/`, исправлены найденные регрессии. Коммит: test(landing): verify routes and responsive states.

### L07 — итоговый отчёт и передача

В отчёте: исходная база, HEAD_SHA, diff --stat, список изменённых файлов, команды и результаты, ссылки на скриншоты, фактические маршруты CTA, готовность видео/FAQ, известные ограничения. Отдельно отметить реальные медиа, утверждённые ответы о данных и прод-маршрут, если ещё не предоставлены. Не объявлять этап принятым только из-за build. Передать на визуальное ревью; production не публиковать в рамках этого задания.

## 6. Итоговые критерии приёмки

- [ ] Mobile совпадает с согласованной последовательностью, видео после заголовка.
- [ ] Desktop реализует расширенную композицию и дополнительные секции.
- [ ] Агент слева, пользователь справа на всех ширинах.
- [ ] Полароид объёмный, CTA заметны, основной текст читаем.
- [ ] Русские шрифты реально загружены; нет случайной подмены.
- [ ] Войти/CTA ведут по подтверждённым маршрутам; нет изменений чужих экранов.
- [ ] Контент демонстрации явно обозначен как пример; нет выдуманных результатов пользователей.
- [ ] Видео, FAQ и состояния доступны с клавиатуры.
- [ ] Сняты текущие screenshots, приложены результаты проверок и SHA.
- [ ] Перед production заменён demo-постер/видео и утверждён текст о данных.

## 7. Что нельзя потерять при реализации

Не использовать ранний вертикальный desktop. Не добавлять score/progress, цены и отзывы без данных. Не превращать диалог в живую AI-форму на лендинге. Не переписывать проект целиком. Не выполнять миграции. Не выдавать чужой иллюстративный портрет за основателя. Не менять тексты и порядок блоков произвольно для удобства CSS.
