# 05. P03–P05: диалог, предложение и сценарий

## 1. Назначение и границы

Подключить рабочий цикл от диалога по мысли через предложение Vocal к сохранённым версиям сценария. Голос в composer — ответ в диалоге, не дубль.

## 2. Предварительные условия и зависимости

- `/reels/[id]` skeleton принят.
- Установлены endpoints/streaming/polling, правила message, proposal, script versions.
- Изучены P03–P05 prototypes и working-cycle sections.

## 3. Точные результаты

- «Диалог»: real history, loading/empty/error/retry, text send без дублей, pending/retry.
- Voice reply использует существующий pipeline/adapter, сохраняется как message/answer и никогда как take.
- AI proposal имеет явные accept/continue actions; повтор безопасен.
- Script создаётся только подтверждённым lifecycle; versions сохраняются/reload.
- «Сценарий»: read/edit/save по contract, явные save/error states.
- Final script хранится отдельно от final take и не меняет его.
- Status transitions только серверно подтверждённые и только канонические labels.

## 4. Не входит в этап

- Recording, video upload, processing, comparison, results.
- Profile questionnaire.
- Auto-generation без user action, новые AI features, manual A/B.
- Final visual polish.

## 5. Критерии приёмки и проверки

- После reload видны messages, proposal state и script versions.
- Duplicate send/accept/save не создаёт duplicates; retry не теряет input.
- Voice reply не попадает в takes и не вызывает take endpoints.
- Proposal→script использует real ids; back/return работают.
- Изменение final script не меняет final take, покрыто test.
- Nav/status canonical; tests/lint/build без новых failures.

## 6. Риски и известные ограничения

- Streaming/reconnect могут дублировать messages: использовать server id/idempotency.
- Async transcription различает pending/failed message и take.
- Autosave/manual save не менять без contract.
- Independent final script может потребовать backwards-compatible migration/rollback.
