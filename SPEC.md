# Vocal — спецификация разового анализатора

> **Статус документа.** Это спецификация **разового анализа** загруженного видео (Job → расшифровка → оценки 0–10). Она описывает уже существующий код и полезна как справочник пайплайна, критериев и контрактов Job.  
> **Требования личного помощника** (мысль → диалог → сценарий → дубли → независимые итоги → завершение) — в [docs/PERSONAL_MVP.md](docs/PERSONAL_MVP.md). Статус этапов — [docs/IMPLEMENTATION_STATUS.md](docs/IMPLEMENTATION_STATUS.md). Если в рабочем плане есть PRODUCT/UI-спеки, они выше макетов.  
> Карточка ролика живёт независимо от Job; статус обработки ≠ готовность ролика; новый дубль не обязательно лучший; финальную запись выбирает автор.

Сервис оценки публичных выступлений: пользователь загружает видео до 3 минут, система извлекает речь, распознаёт текст с таймстампами и выдаёт оценки плюс рекомендации.

**Жёсткие технологии**

| Этап | Технология | Модель / инструмент |
|---|---|---|
| Видео → аудио | FFmpeg | MP3, 16 kHz, mono, 64 kbps |
| Аудио → текст | Groq Speech-to-Text | `whisper-large-v3-turbo` (по умолчанию), fallback `whisper-large-v3` |
| Анализ и рекомендации | Groq Chat Completions | `openai/gpt-oss-120b` (качество), fallback `openai/gpt-oss-20b` |

> Groq ≠ Grok. Grok — модель xAI. По ТЗ анализ идёт **через Groq API**. Llama 3.3 70B / Llama 3.1 8B на Groq снимают 16.08.2026 — в MVP их не используем.

## 1. Общая архитектура

Один Next.js-приложение: вебморда, API и пайплайн обработки. Состояние джобы в БД, файлы на диске (MVP). Прогресс — polling статуса каждые 1–2 секунды.

```
Браузер
  │  POST /api/uploads  (видео ≤ 3 мин)
  ▼
Next.js API
  │  1. валидация (тип, размер, длительность через ffprobe)
  │  2. сохранить видео, создать job: queued
  ▼
Job worker (тот же процесс, очередь в памяти / БД)
  │
  ├─ converting   FFmpeg → MP3 16kHz mono 64kbps
  ├─ transcribing Groq STT (ru, verbose_json, timestamps)
  ├─ analyzing    метрики по таймстампам + Groq LLM (критерии)
  └─ done | error
  │
  ▼
GET /jobs/:id     результат: расшифровка + оценки + рекомендации
GET /jobs         история загрузок
GET/PUT /criteria настройки критериев
```

### Поток данных

```
видео (webm/mp4/mov)
        │
        ▼
   FFmpeg extract
        │
        ▼
   audio.mp3  ──►  Groq Whisper  ──►  transcript + segments[]
                                              │
                    derived metrics ◄─────────┤  WPM, паузы, паразиты
                                              │
                    criteria config ──────────┤
                                              ▼
                                       Groq LLM (JSON)
                                              │
                                              ▼
                         result: scores + recommendations + transcript
```

### Статусы джобы

`queued` → `converting` → `transcribing` → `analyzing` → `done`  
на любом шаге → `error` (+ `error_code`, `error_message`)

## 4. Пайплайн: видео → результат

### 4.1. Видео → аудио (FFmpeg)

Цель: минимальный файл, достаточный для Whisper. Whisper внутри работает на 16 kHz mono — выше семплрейт и стерео не дают качества распознавания, только размер.

**Команда**

```bash
ffmpeg -y -i input.mp4 \
  -vn \
  -ac 1 \
  -ar 16000 \
  -c:a libmp3lame \
  -b:a 64k \
  output.mp3
```

| Параметр | Значение | Почему |
|---|---|---|
| Формат | MP3 (`libmp3lame`) | Малый размер, Groq принимает |
| Каналы | mono (`-ac 1`) | Речь, −50% к размеру vs stereo |
| Sample rate | 16 000 Hz | Натив для Whisper |
| Битрейт | 64 kbps | Речи достаточно; 3 мин ≈ 1.4 MB |
| Видеодорожка | отброшена (`-vn`) | Не нужна для STT |

Длительность до конвертации — `ffprobe`. Если `> 180` сек — отказ, FFmpeg не запускаем.

Оригинал видео хранить до `done` (повторный прогон). После успеха MVP может удалять оригинал, оставляя mp3.

### 4.2. Аудио → текст (Groq STT)

**Запрос**

```ts
client.audio.transcriptions.create({
  file: fs.createReadStream(mp3Path),
  model: "whisper-large-v3-turbo",
  language: "ru",
  response_format: "verbose_json",
  timestamp_granularities: ["segment", "word"],
  temperature: 0,
  prompt: "Публичное выступление на русском языке.",
});
```

- `language: "ru"` — точность и скорость (без автодетекта по первым 30 сек).
- `verbose_json` + сегменты и слова — таймкоды для рекомендаций («замедлитесь на 0:42–0:55»).
- Turbo по умолчанию; при пустом тексте / высокой `no_speech_prob` — один повтор на `whisper-large-v3`.

**Лимиты Groq:** файл до ~100 MB; 3 мин MP3 64k ≈ 1.4 MB — запас большой.

**Ошибки STT**

| Ситуация | Действие |
|---|---|
| 429 rate limit | retry 3 раза, backoff 2s / 4s / 8s |
| 413 / file too large | `error`, просить более короткий ролик |
| сеть / 5xx | retry, затем `error` |
| пустой транскрипт | retry на `whisper-large-v3`; если снова пусто — `error`: «речь не распознана» |
| нерусский язык | всё равно транскрибировать с `ru`; в анализе пометить риск ошибок |

Сохраняем: полный текст, `segments[]` (`start`, `end`, `text`), опционально `words[]`.

### 4.3. Метрики по расшифровке (без LLM)

Считаем детерминированно и передаём в модель оценки:

- темп: слов / минуту (глобально и по окнам 15–20 сек);
- паузы: разрывы между сегментами > 0.7 сек (количество, средняя, макс);
- слова-паразиты: «ну», «вот», «как бы», «типа», «короче», «в общем», «это самое», «так сказать», «значит», «ээ», «эм» + частота на 100 слов;
- доля длинных сегментов без пауз ( Speeding );
- длина выступления vs лимит 3 мин.

Это якорь: LLM не выдумывает темп, а интерпретирует цифры.

### 4.4. Оценка ораторства (Groq LLM)

Вход: транскрипт, сегменты с таймстампами, метрики, **только включённые критерии и их веса**.

Выход — строго JSON (Zod). `temperature: 0.2`, `response_format: json_object`.

Модель не ставит оценки за жесты, взгляд, слайды, громкость — этого нет во входе. Только речь + ритм по таймкодам.

## 5. Шесть блоков функционала

### 5.1. Видео → аудио (FFmpeg)

См. §4.1. Обёртка `lib/ffmpeg.ts`: `probeDuration(path)`, `extractAudio(input, output)`. Таймаут процесса ~60 сек. Логи stderr при `error`.

### 5.2. Аудио → текст (Groq STT)

См. §4.2. `lib/stt.ts`. Русский зафиксирован. Таймстампы обязательны для MVP (сегменты минимум; слова — желательно).

### 5.3. Веб-интерфейс загрузки

- Drag-and-drop + кнопка выбора файла.
- Форматы: `mp4`, `webm`, `mov`, `mkv`.
- Клиент: проверка размера (`MAX_UPLOAD_MB`) и, если браузер даёт duration, длины ≤ 3 мин.
- Сервер: повторная проверка `ffprobe` — источник правды.
- После POST — редирект на `/jobs/[id]`.
- На странице джобы — степпер: Загрузка → Конвертация → Распознавание → Анализ.
- Текущий шаг — спиннер, завершённый — галочка, ошибка — текст и «Повторить».

Без авторизации в MVP: все джобы видны локально (один пользователь / один инстанс).

### 5.4. Страница результата

После `done`:

1. **Итоговый балл** 0–10 (взвешенная сумма включённых критериев).
2. **Карточки критериев** — балл, короткий комментарий.
3. **Рекомендации** — приоритет (высокий / средний / низкий), что исправить, таймкод, цитата из расшифровки.
4. **Расшифровка** — сегменты, подсветка паразитов и фрагментов из рекомендаций, клик по сегменту скроллит к совету.
5. **Метрики** — WPM, паузы, плотность паразитов (цифры, не «ощущения»).

Состояния: прогресс, ошибка, результат. Обновление — polling `GET /api/jobs/:id` раз в 1.5 сек, пока не `done`/`error`.

### 5.5. История загрузок

Список `/history`: дата, имя файла, длительность, статус, итоговый балл, 1–2 главные рекомендации.

Фильтр по статусу. Клик — карточка результата. В MVP без удаления; кнопка «удалить» — простой плюс, не блокер.

### 5.6. Критерии анализа (полный набор + настройки)

Хранятся в БД. Дефолты сидятся при старте. Пользователь включает/выключает и меняет вес (1–5). Выключенный критерий не входит в промпт и в итоговый балл.

**Итоговый балл**

```
score = Σ (criterion_score * weight) / Σ weights
        только по enabled = true
```

#### Базовый набор (MVP)

| id | Критерий | Что оцениваем | Вес по умолчанию |
|---|---|---|---|
| `structure` | Структура | Вступление, основная часть, вывод | 5 |
| `thesis` | Ясность тезиса | Понятна ли цель/мысль выступления | 5 |
| `argumentation` | Аргументация | Примеры, факты, обоснования | 4 |
| `coherence` | Связность | Логика переходов, отсутствие скачков | 4 |
| `filler_words` | Слова-паразиты | Частота и заметность канцелярита/паразитов | 5 |
| `vocabulary` | Лексика | Точность формулировок, разнообразие | 3 |
| `tempo` | Темп | WPM: норма ~110–160 для русской речи | 5 |
| `pauses` | Паузы | Есть ли дыхание и акценты; нет провалов и «скороговорки» | 4 |
| `confidence` | Уверенность | Хеджирование («как бы», «наверное») vs прямые формулировки | 3 |
| `specificity` | Конкретность | Факты vs «вода» | 4 |
| `audience` | Контакт с аудиторией | Обращения, вопросы, «мы», призыв | 3 |
| `ending` | Сильное завершение | Вывод / CTA, не обрыв | 4 |

#### Расширение (включить в UI, выключить по умолчанию)

| id | Критерий |
|---|---|
| `rhetoric` | Риторические приёмы (аналогии, повтор, контраст) |
| `emotion` | Эмоциональная окраска лексики |
| `repetition` | Тавтология и хождение по кругу |
| `density` | Информационная плотность на минуту |
| `grammar` | Ломаные фразы (с оговоркой: это может быть ошибка STT) |

Настройки — `/settings`: чекбоксы, слайдеры весов, «сбросить к дефолту». Новые загрузки берут актуальный конфиг; старые результаты не пересчитываются сами (кнопка «пересчитать» — после MVP).

## 6. Контракты данных

### Job

```ts
type JobStatus =
  | "queued"
  | "converting"
  | "transcribing"
  | "analyzing"
  | "done"
  | "error";

interface Job {
  id: string;
  originalName: string;
  videoPath: string;
  audioPath?: string;
  durationSec?: number;
  status: JobStatus;
  errorCode?: string;
  errorMessage?: string;
  createdAt: string;
  updatedAt: string;
}
```

### Результат анализа (LLM + метрики)

```ts
interface AnalysisResult {
  overallScore: number; // 0–10, 1 знак
  summary: string;      // 2–4 предложения
  metrics: {
    durationSec: number;
    wordsPerMinute: number;
    pauseCount: number;
    avgPauseSec: number;
    fillerPer100Words: number;
    wordCount: number;
  };
  scores: Array<{
    criterionId: string;
    score: number;      // 0–10
    comment: string;    // 1–2 предложения
  }>;
  recommendations: Array<{
    priority: "high" | "medium" | "low";
    title: string;
    detail: string;
    startSec?: number;
    endSec?: number;
    quote?: string;
  }>;
  transcript: {
    text: string;
    segments: Array<{ start: number; end: number; text: string }>;
  };
}
```

## 7. Поэтапный план (приоритеты)

| Этап | Что | Приоритет | Результат |
|---|---|---|---|
| **0. Каркас** | Next.js, Prisma, FFmpeg probe, `.env`, страница загрузки-заглушка | P0 | Проект поднимается |
| **1. Конвертация** | Upload → ffprobe ≤ 3 мин → MP3 → статус `converting` | P0 | Файл в `storage/audio` |
| **2. STT** | Groq Whisper ru + timestamps, ошибки/retry | P0 | Расшифровка на экране |
| **3. Оценка** | Метрики + критерии + Groq JSON + страница результата | P0 | Баллы и рекомендации |
| **4. Прогресс UI** | Степпер и polling | P0 | Понятный процесс |
| **5. История** | Список джоб с баллом и 1–2 советами | P1 | `/history` |
| **6. Критерии** | Вкл/выкл, веса, дефолты | P1 | `/settings` |
| **7. Полировка** | Паразиты в транскрипте, таймкоды в советах, пустой звук, retry | P2 | Удобный MVP |

Порядок не ломать: без 1–3 нет продукта; 5–6 — сразу после рабочего пайплайна.

## 9. Риски

| Риск | Влияние | Митигация |
|---|---|---|
| FFmpeg нет в PATH (Windows) | Пайплайн мёртв | Проверка при старте; в README точная установка; ошибка в UI, не silent fail |
| Groq 429 / простой | Нет STT и анализа | Retry + backoff; очередь из одной джобы в MVP; понятное сообщение |
| Снятие Llama на Groq (16.08.2026) | Сломан анализ | Сразу `openai/gpt-oss-120b`, модель в env |
| Путаница Groq / Grok | Неверный API | Только Groq; ключ `GROQ_API_KEY` |
| Whisper путает русскую речь / шум | Кривые оценки | `language=ru`, prompt, fallback v3, порог `no_speech_prob` |
| LLM ломает JSON | Нет результата | `json_object` + Zod; 1 retry с «верни только JSON» |
| Оценки «из воздуха» | Нет доверия | Метрики считаем сами; в промпте запрет выдумывать WPM/паузы |
| Видео > 3 мин / огромный файл | Нагрузка и деньги | Жёсткий ffprobe + лимит MB до FFmpeg |
| Нет акустики (громкость, интонация) | Завышенные ожидания | В UI явно: оценка **речи и структуры**, не жестов и голоса |
| STT без слов-таймстампов | Советы без привязки | Сегменты обязательны; word-level — best effort |
| Локальная SQLite / диск | Не для мультипользователя | Ок для MVP; миграция на Supabase — следующий этап |

## 10. Что не входит в MVP

- Аккаунты, биллинг, шаринг ссылок.
- Оценка жестов, взгляда, слайдов, громкости.
- Видео длиннее 3 минут и нарезка чанков.
- Живой стрим / запись с веб-камеры (можно следующим шагом: MediaRecorder → тот же пайплайн).
- Сравнение двух выступлений, экспорт PDF.
- Очередь воркеров и горизонтальное масштабирование.

## 11. Критерии готовности разового анализатора (этот документ)

1. Загрузка ролика ≤ 3 мин, отказ более длинного.
2. Конвертация в MP3 16 kHz mono 64 kbps через FFmpeg.
3. Русская расшифровка с сегментными таймстампами через Groq Whisper.
4. Страница с итоговым баллом, баллами по критериям, рекомендациями и текстом.
5. Степпер прогресса по шагам пайплайна.
6. История загрузок.
7. Настройка критериев (вкл/выкл и веса) влияет на новый анализ.
8. Ошибки FFmpeg/Groq видны пользователю, без падения сервера.
