# Генеративные принципы для Vocal

### Сузить категоричное утверждение

**Когда применять:** пользователь приносит миф, страшилку или формулу «всегда/никогда/точно».

**Вход:** исходное утверждение, предполагаемая причинность, исключения и условия.

**Ход:** `воспроизвести утверждение → назвать ошибочный переход → дать более узкое правило → обозначить исключение → предложить действие`

**Проверка:** итог не просто отрицает тезис, а объясняет, в каком условии он неверен или требует уточнения.

**Риск:** заменить одну категоричность другой или выдать отраслевое мнение за установленный факт.

### Развести смешиваемые категории

**Когда применять:** аудитория путает тест и диагноз, риск и событие, симптом и причину, норму и показание.

**Вход:** две категории, вопрос каждой категории, точность и границы вывода.

**Ход:** `назвать путаницу → определить категорию A → определить категорию B → сравнить ответы и ограничения → показать выбор по условию`

**Проверка:** после сценария можно одним предложением ответить, что доказывает A и чего не доказывает B.

**Риск:** создать ложную бинарность там, где вариантов больше двух.

### Перевести число в решение

**Когда применять:** есть риск, диапазон, порог или сравнительная статистика.

**Вход:** число, знаменатель, сравнение, практический порог.

**Ход:** `дать число → назвать единицу и масштаб → сравнить с релевантной базой → объяснить, что меняется в решении`

**Проверка:** число не остаётся декоративным и не меняет смысл при переходе от относительного риска к абсолютному.

**Риск:** ложная точность, неверный знаменатель, отсутствие источника или внешней проверки.

### Случай → механизм → правило

**Когда применять:** есть реальная история, случай из практики или публичный эпизод.

**Вход:** короткая сцена, причинная гипотеза, границы обобщения, действие.

**Ход:** `показать последствие → назвать механизм → отделить частный случай от частоты → дать общее правило → указать альтернативы`

**Проверка:** правило не следует только из эмоциональной силы истории.

**Риск:** анекдотическое доказательство, нарушение приватности, драматизация риска.

### Личный опыт → общий вопрос

**Когда применять:** пользователь хочет начать с собственного опыта, не превращая его в универсальный совет.

**Вход:** событие, личное решение, общие данные, индивидуальные ограничения.

**Ход:** `личная сцена → вопрос, который она поднимает → общий механизм → условия применимости → оговорка «мой опыт не равен норме для всех»`

**Проверка:** зритель может отделить «что было со мной» от «что обычно следует делать».

**Риск:** скрытое обобщение единичного опыта или самодиагностика.

### Объект → устройство → выбор

**Когда применять:** есть предмет, схема, анализ, прибор или демонстрация процедуры.

**Вход:** объект, его части, функция, показания и ограничения.

**Ход:** `назвать объект → показать части → связать часть с функцией → объяснить применение → обозначить границу`

**Проверка:** каждое упоминание детали помогает понять функцию или решение.

**Риск:** текст предполагает визуал, которого нет; демонстрация может быть воспринята как индивидуальная инструкция.

### Список с единой осью

**Когда применять:** нужно дать несколько правил, порогов или вещей, которых стоит избегать.

**Вход:** единый вопрос, 3–5 элементов, короткое основание каждого.

**Ход:** `обозначить ось списка → элемент → причина/последствие → следующий элемент → общий критерий выбора`

**Проверка:** все пункты отвечают на один вопрос и расположены по понятному принципу.

**Риск:** список без причин, смешение разных уровней или избыточное число пунктов.

### Спроектировать функцию финала

**Когда применять:** после объяснения нужно завершить ролик без механического пересказа.

**Вход:** тезис, область применимости, безопасное следующее действие.

**Ход:** `сжать вывод → назвать условие → предложить одно действие → при необходимости задать вопрос`

**Проверка:** действие логически следует из содержания и не маскирует рекламу под медицинскую необходимость.

**Риск:** тревожный CTA, обещание результата, навязчивая продажа или рекомендация вне компетенции.

## Что не переносить

- Характерные фразы, панчлайны, резкие оценки, ругательства и речевые привычки автора.
- Личную беременность, семейные сцены, пациентов, биографию и узнаваемых персонажей.
- Голос гостей, реплики из фильмов и чужих роликов.
- Медицинские, статистические и исторические утверждения без компетенции и проверки.
- Рекламные обещания и приглашения на продукты автора.
- Поверхностную стилизацию, если не перенесена сама логическая операция.

## Обновление после глубокого Prompt 1–3

### Конструктор пяти решений

**Когда применять:** перед написанием разговорного сценария.

**Вход:** мысль пользователя и исходный материал.

**Ход:** `источник входа → смысловая операция → тип опоры → граница → одна функция финала`

**Проверка:** каждый элемент называется отдельно; опора поддерживает операцию; финал не меняет задачу незаметно.

**Риск:** превратить решения в механическую анкету и потерять естественную речь.

### Оператор границы вывода

**Когда применять:** есть числа, профессиональные утверждения, единичный случай, личный опыт или категоричные слова.

**Вход:** тезис, условия, исключения и недостающие данные.

**Ход:** `самое сильное обобщение → чего материал не доказывает → условие/исключение → проверка основного тезиса`

**Проверка:** граница конкретна: «не единственная причина», «не для всех», «метрика не отвечает на этот вопрос».

**Риск:** перегруз оговорками или формальная приписка.

### Выбор архитектуры по нагрузке

**Когда применять:** после извлечения тезисов, до генерации.

**Вход:** число самостоятельных тезисов, ветвей, спикеров и тем.

**Ход:** `одна операция → single_move; зависимые ветви → decision_tree; темы/спикеры → long_form_segmentation; ненадёжная атрибуция → mixed_or_unattributed`

**Проверка:** в `single_move` один тезис; в дереве у каждой ветви есть условие; в длинном источнике каждый кандидат автономен и атрибутирован.

**Риск:** делить только по длине, а не по смысловым границам.

### Разделить образование и оффер

**Когда применять:** есть продажа, приглашение или ссылка на продукт.

**Вход:** образовательный тезис, опора, оффер и обещание.

**Ход:** `завершить доказательную цепочку → поставить границу → сформулировать оффер отдельно → удалить недоказанное обещание`

**Проверка:** без оффера образовательный тезис остаётся целым.

**Риск:** скрытая реклама и подмена доказательства авторитетом продукта.

### Разделить конкурирующие тезисы

**Когда применять:** один ID содержит два вывода, много вопросов или смену темы.

**Вход:** локальные тезисы и переходы.

**Ход:** `разметить тезисы → найти общий вопрос → при его отсутствии создать отдельные кандидаты → каждому дать вход и финал`

**Проверка:** каждый кандидат понятен без соседнего фрагмента.

**Риск:** искусственно создать серию из зависимых обрывков.
