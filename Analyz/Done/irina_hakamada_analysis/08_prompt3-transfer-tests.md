# Prompt 3 — перенос в Vocal и тесты

## 1. Маршрутизатор смысловой операции

**Вход:** вопрос пользователя, его опыт, желаемая функция ролика.

**Решение:** выбрать один основной маршрут:

1. смешаны значения → разделить понятия;
2. есть два реальных режима → сопоставить полюса и критерий переключения;
3. непонятна причинность → построить ограниченную мини-модель;
4. мысль слишком абстрактна → выбрать функцию примера;
5. понятна проблема, но нет выхода → превратить в безопасный следующий шаг;
6. задача — продажа/анонс/сцена → не выдавать её за нейтральное объяснение.

**Тест:** маршрут должен менять структуру ответа; случайно добавленный контраст или пример не считается операцией.

## 2. Разделитель голосов

**Правило:** вопрос интервьюера хранится как `prompt_voice`, авторское преобразование — как `author_operation`.

**Тест:** после удаления вопроса должно быть видно, какая часть механики действительно принадлежит ответу. Если ответ не самодостаточен, система помечает зависимость от вопроса.

## 3. Конструктор различий

**Ход:** `найти расплывчатое слово → предложить 2–3 возможных значения → выбрать релевантное → показать, как меняется ответ`.

**Тесты:**

- значения не являются случайными антонимами;
- для каждого значения можно привести наблюдаемый критерий;
- исходный вопрос не исчезает после уточнения;
- нет ложной бинарности.

## 4. Выбор функции примера

Перед созданием примера задать один режим:

- проиллюстрировать;
- проверить на малой модели;
- показать процедуру;
- раскрыть личный опыт;
- создать желаемую картину продукта.

**Тест:** пример выполняет одну названную функцию и не выдаётся за доказательство, если он только иллюстрирует.

## 5. Проверка основания утверждения

Каждое общее утверждение получает метку:

- `TEXT_ONLY` — связно внутри истории, но не проверено;
- `PERSONAL_EXPERIENCE` — основано на опыте пользователя;
- `EXAMPLE` — один случай;
- `EXTERNAL_EVIDENCE_NEEDED` — требуется источник или специалист;
- `BOUNDED_ADVICE` — действие ограничено безопасной областью.

**Тест:** категорические слова «всегда», «только», «все», «единственный» вызывают отдельную проверку альтернатив и контрпримеров.

## 6. Безопасный перевод в действие

**Ход:** `описать наблюдаемый симптом → перечислить альтернативные причины → выбрать малый обратимый шаг → указать стоп-условие → назвать критерий результата`.

**Тест:** медицинская, психологическая, юридическая или финансовая причинность не выводится из личного эпизода. Для `DazWKGtt7Qt` переносима структура «наблюдение → проверка → действие», но не утверждение о происхождении боли.

## 7. Селектор функции финала

Перед финалом выбрать одно:

- действие;
- критерий выбора;
- смысловое сжатие;
- честная граница знания;
- CTA, явно отмеченный как коммерческий;
- открытая сцена без претензии на тезис.

**Тест:** финал не вводит новую причинность и не обещает эффект, которого не было в рассуждении.

## 8. Минимальный машинный контракт

```json
{
  "input_frame": "question | claim | story | promo | scene",
  "prompt_voice": "user | interviewer | author | mixed",
  "author_operation": "distinguish | contrast | model | exemplify | prescribe | refuse",
  "example_function": "none | illustrate | test | demonstrate | personalize | sell",
  "claim_basis": "TEXT_ONLY | PERSONAL_EXPERIENCE | EXAMPLE | EXTERNAL_EVIDENCE_NEEDED | BOUNDED_ADVICE",
  "ending_function": "action | criterion | compression | boundary | cta | scene",
  "counterexample_checked": true,
  "risk_note": "string or null"
}
```

## 9. Приёмочные проверки генератора

1. Может ли система объяснить, какое различие она ввела и зачем?
2. Остаётся ли тезис понятным после удаления ярких фраз и стилизации автора?
3. Не приписан ли вопрос интервьюера автору?
4. Соответствует ли пример выбранной функции?
5. Отделены ли связность текста, доказанность и безопасность?
6. Есть ли хотя бы одна альтернативная причина для категорического объяснения?
7. Следует ли финал из предыдущих шагов?
8. Можно ли использовать структуру для другой темы без копирования позиции Ирины Хакамады?
