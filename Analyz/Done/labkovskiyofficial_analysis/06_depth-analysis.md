# Глубокий Prompt 1–3: 24 выбранные записи

## Метод

Глубокий проход выполнен только по трём заранее зафиксированным выборкам из `04_depth-selections.md`. Решения Prompt 0 не менялись. Каждый ID разбирался отдельно; чужая речь не приписывалась автору; истинность психологических и медицинских утверждений не проверялась.

### Поля разбора

- **Вход** — наблюдаемая форма начала.
- **Тезис** — утверждение, которое возможно восстановить из одного ID.
- **Операция** — преобразование исходной постановки.
- **Опора** — чем текст поддерживает переход: критерий, пример, причинная связка, перечисление, аналогия или личная история.
- **Финал** — функция последней части.
- **Граница** — чего данный текст не доказывает.
- **Для Vocal** — переносимая операция без копирования голоса автора.

# Prompt 3. Синтез и проверка модели

## Проверенная архитектура сценария

Глубокий проход не подтверждает один универсальный каркас. Он поддерживает двухэтапную модель:

1. **Определить режим:** Q&A-рефрейм, объяснение различия, инструкция/кодекс, личный кейс, диалог, панчлайн, граница или промо.
2. **Выбрать одну доминирующую операцию:** заменить объект решения, провести различение, построить развилку, показать причинную цепь, операционализировать примером, ограничить знание или выполнить CTA.

После этого отдельно выбираются:

- **опора:** факт из входа, критерий, микропример, контраст, сценарий, аналогия, личный опыт;
- **функция финала:** действие, вердикт, граница, открытый вопрос, оговорка либо CTA;
- **уровень уверенности:** установлено в тексте, интерпретация, предположение, неизвестно.

## Новая главная гипотеза

В данном корпусе повторяется не один сценарный шаблон, а **операция смыслового сжатия**: из многозначной ситуации выбирается один доминирующий объект решения, критерий или причинная рамка. В Q&A это часто выглядит как рефрейм с последующим действием; в объяснениях — как различение; в инструкциях — как правило; в личных кейсах — как причинная хронология; в рекламе — как частичный тезис, ведущий к CTA.

**Статус: REFINED, а не универсально подтверждённая модель.** Корпус показывает повторяемость операций, но не доказывает их полноту, истинность или эффективность.

## Практическое следствие для Vocal

Генератору не следует начинать с заполнения одного шаблона. Сначала он должен спросить или определить:

1. Какой результат нужен: объяснить, помочь выбрать, дать инструкцию, рассказать кейс, поставить границу или продвинуть предложение?
2. Какой объект действительно можно изменить или проверить?
3. Какая одна операция будет центром ролика?
4. Какая опора допустима по данным и компетенции пользователя?
5. Какую функцию должен выполнить финал?

Только после этих решений формируется текст. Это уменьшает риск однообразных «рефреймов», ложной категоричности и копирования поверхности автора.

- Что найденные операции повышают просмотры, удержание, доверие или продажи.
- Что заявленные психологические и медицинские причинные связи верны.
- Что смешанные реплики принадлежат автору.
- Что текстовая структура совпадает с визуальной структурой ролика.
- Что риторический пример является доказательством тезиса.
