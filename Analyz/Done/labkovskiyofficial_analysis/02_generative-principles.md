# Генеративные принципы для Vocal

Это не шаблоны реплик Михаила Лабковского. Ниже — переносимые операции построения мысли, подтверждённые или уточнённые в корпусе.

## Обновление после глубокого Prompt 1–3: маршрутизатор до генерации

Глубокий анализ показал, что единый каркас сделал бы сценарии однообразными. До применения операций ниже Vocal должен определить один основной режим:

| Режим | Главная задача | Базовый ход |
|---|---|---|
| Q&A-рефрейм | изменить объект решения | `вопрос → скрытая предпосылка → новая рамка → следствие` |
| Объяснение различия | развести смешанные понятия | `общее → критерий различия → параллельные примеры → граница` |
| Инструкция/кодекс | дать выполняемое правило | `цель → правило → ограничения → минимальное применение` |
| Личный кейс | показать опыт без универсализации | `до → изменение → после → что осталось неизменным → ограничение` |
| Диалог | проявить конфликт позиций | `позиция A → уточнение → позиция B → вариант решения` |
| Панчлайн/граница | дать один короткий ответ | `формулировка → разворот или граница → завершение` |
| Продвижение | связать проблему с предложением | `проблема → полезный минимум → недостающая глубина → CTA` |

После выбора режима система отдельно выбирает **одну доминирующую операцию**, **тип опоры**, **функцию финала** и **уровень уверенности**. Если режим определить нельзя, система задаёт уточняющий вопрос, а не генерирует усреднённый сценарий.

### Контроль эпистемической уверенности

**Когда применять:** всегда, особенно при психологических, медицинских и причинных утверждениях.

**Вход:** факты пользователя, интерпретации, термины, источники и границы компетенции.

**Ход:** `разделить факт и интерпретацию → пометить уверенность → сохранить оговорку → удалить неподдержанный диагноз`

**Проверка:** каждое уверенное утверждение либо дано пользователем, либо обосновано допустимым источником; предположение остаётся предположением.

**Риск:** усиливать сомнительную фразу ради убедительности сценария.

### Проверка реальных ограничений перед возвратом агентности

**Когда применять:** сценарий собирается сказать человеку «это ваш выбор» или предложить немедленный выход.

**Вход:** признаки угроз, насилия, зависимости, болезни, финансовых и правовых ограничений.

**Ход:** `проверить безопасность → назвать реальные ограничения → определить доступную зону влияния → только затем предложить действие`

**Проверка:** совет не обвиняет человека в ситуации, которую он фактически не контролирует.

**Риск:** виктимблейминг и опасное упрощение.

### Проверка предпосылки вопроса

**Когда применять:** вопрос уже содержит причинное объяснение, ярлык или чужое решение как данность.

**Вход:** вопрос пользователя, заявленные факты, предполагаемая причина.

**Ход:** `выделить факт → отделить интерпретацию → найти скрытую предпосылку → предложить нейтральный контртезис`

**Проверка:** контртезис опирается на слова пользователя и не требует выдуманной биографии.

**Риск:** превратить проверку предпосылки в резкое отрицание или необоснованный диагноз.

### Перенос к контролируемому действию

**Когда применять:** герой пытается узнать чужие мысли, изменить другого или получить гарантию будущего.

**Вход:** объект тревоги, доступные решения героя, реальные ограничения.

**Ход:** `назвать неконтролируемое → определить зону влияния → сформулировать одно решение → назвать ближайший шаг`

**Проверка:** действие может выполнить сам герой и оно не обещает контроля над другим человеком.

**Риск:** переложить на человека ответственность за чужое насилие, болезнь или системное ограничение.

### Развилка по критерию

**Когда применять:** общий вопрос скрывает несколько принципиально разных ситуаций.

**Вход:** 2–3 наблюдаемых признака, возможные варианты, цена ошибки.

**Ход:** `назвать различие → задать критерий → построить ветки → дать отдельное следствие для каждой`

**Проверка:** ветки взаимно различимы, а критерий можно проверить без чтения мыслей.

**Риск:** ложная бинарность и исключение важных вариантов.

### Бытовая операционализация

**Когда применять:** тезис остаётся абстрактным — «выбирать себя», «уважать решение», «меньше бояться».

**Вход:** тезис, знакомая аудитории ситуация, одно наблюдаемое действие.

**Ход:** `выбрать микросцену → показать решение в сцене → связать действие с тезисом → убрать лишнюю мораль`

**Проверка:** зритель может пересказать сцену и объяснить, какую операцию она демонстрирует.

**Риск:** выдать удачную иллюстрацию за доказательство общего правила.

### Минимальный следующий шаг

**Когда применять:** задача пугает объёмом или сформулирована как неопределённое «начать».

**Вход:** конечная задача, первая доступная дата, минимальный фрагмент работы.

**Ход:** `сократить горизонт → назначить момент → выбрать минимальный объём → определить признак выполнения`

**Проверка:** шаг конкретен по времени или результату и не равен всей задаче.

**Риск:** механически предлагать действие там, где сначала нужна безопасность, диагностика или помощь специалиста.

### Финал с выбранной функцией

**Когда применять:** мысль уже развита, но ролик заканчивается размыто.

**Вход:** основной тезис и желаемый эффект финала.

**Ход:** `выбрать функцию → убрать новый аргумент → сформулировать действие/границу/вопрос/вывод → при необходимости отдельно добавить CTA`

**Проверка:** финал выполняет одну функцию и не подменяет содержание рекламой.

**Риск:** скопировать характерный панчлайн или агрессивную директивность автора.

### Проблема → ограниченный CTA

**Когда применять:** ролик действительно продвигает событие или продукт.

**Вход:** проблема аудитории, один полезный вывод, содержание предложения, CTA.

**Ход:** `обозначить проблему → дать минимальный содержательный результат → назвать недостающую глубину → предложить следующий шаг`

**Проверка:** до CTA есть самостоятельная ценность, а обещание соответствует предложению.

**Риск:** оборвать объяснение сразу после тревожной постановки или дать непроверяемое рекламное обещание.

### Перевод профессионального ярлыка в наблюдение

**Когда применять:** сценарий использует термин как готовое объяснение.

**Вход:** термин, наблюдаемое поведение, границы компетенции, при наличии — проверенные источники.

**Ход:** `назвать наблюдение → отделить термин от диагноза → описать возможную связь → указать границу знания`

**Проверка:** без термина остаётся понятная и проверяемая мысль.

**Риск:** псевдодиагностика, медицинская дезинформация и подмена причин ярлыками.

## Что не переносить

- характерные фразы, панчлайны и буквальные развороты автора;
- личную историю, биографию, гонорары и медицинский опыт автора;
- узнаваемых персонажей, анекдоты и культурные ссылки;
- ругательства, резкие обращения и речевые привычки;
- психологические, медицинские и нейробиологические утверждения вне компетенции нового пользователя;
- реплики гостей и вопросы интервьюера как авторский голос;
- рекламные обещания и названия мероприятий;
- категоричность, если она не следует из входных данных;
- любые поверхности, которые копируют автора вместо операции мысли.
