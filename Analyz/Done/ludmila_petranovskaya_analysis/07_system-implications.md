# Выводы для системы Vocal после глубокого прохода

## Что изменить в модели данных

Для сценария недостаточно полей `hook`, `thesis`, `example`, `cta`. Нужны отдельные поля:

```json
{
  "content_mode": "expert_explainer | personal_observation | promo | interview_source | comic_fragment",
  "automatic_frame": "какое очевидное толкование останавливаем",
  "distinction": {
    "side_a": "первое явление",
    "side_b": "второе явление",
    "criterion": "наблюдаемый признак"
  },
  "causal_model": ["событие", "реакция", "следствие"],
  "alternative_causes": [],
  "role_shift": {
    "from": "неработающая роль",
    "to": "рабочая роль"
  },
  "evidence_function": "contrast | counterfactual | causal_scene | analogy | case | none",
  "residual_reality": "что не исчезнет после рекомендации",
  "final_function": "position | conditional_action | normalization | open_loop | audience_question | transparent_promo",
  "speaker_attribution": "author | guest | mixed",
  "knowledge_boundary": "граница компетенции/данных"
}
```

## Что изменить в маршрутизации

1. Сначала определять `content_mode`; не отправлять личную зарисовку в генератор экспертного опровержения.
2. Длинные эфиры направлять в отдельный extractor: вопросы, возражения, кейсы и тезисы по спикерам.
3. Почти повторы хранить как связанную группу и не использовать как независимые подтверждения.
4. После выбора причины выбирать роль и финал; не генерировать совет раньше диагностического критерия.
5. Требовать поле `residual_reality`, чтобы сценарий не обещал исчезновения конфликта, чувства или ограничения.

## Новые автоматические проверки

- Если есть два понятия, но нет критерия — вернуть сценарий на уточнение.
- Если перечислены причины, но нет признаков различения — пометить как декоративную многофакторность.
- Если аналогия длиннее тезиса и нет явного соответствия — запросить связь одним предложением.
- Если `speaker_attribution != author` — запретить обучение авторскому паттерну без ручной атрибуции.
- Если `content_mode = promo`, проверить, остаётся ли самостоятельная мысль без CTA.
- Если совет обещает устранить исходную проблему полностью — запросить реалистичный остаток и границу применимости.

## Практический приоритет

Для MVP полезнее всего реализовать четыре операции: `diagnostic distinction`, `cause tree`, `escalation loop`, `role shift`. Они покрывают основную глубину корпуса и не требуют копировать авторскую поверхность. Извлечение из длинных эфиров стоит держать отдельным исследовательским модулем, а не смешивать с генератором коротких сценариев.
