- дата: 20-Aug-2026
- вход: [hadunkin закрыт](00_plan.md) · [метод](01_method-review.md) · [оптимизация](02_optimization.md)

Полный проход hadunkin — калибровочный эксперимент, не будущий стандарт. Воронка обязательна. Критерий качества — не «сколько роликов разобрано».

**Метрика процесса:** сколько новых утверждений о способе мышления автора **выдержали попытку их опровергнуть**.

---

## 0. Вопрос эксперимента №2

Не: «Как устроен автор №2?»

Да: **что из найденного у автора №1 переживает столкновение с совершенно другим автором?**

Самый ценный артефакт после второго корпуса — не его разбор, а таблица:

`hadunkin | Author B | общее | различное | пока неизвестно`

С неё отделяются универсальные ходы мышления от индивидуального почерка. Это и есть зародыш архитектуры Vocal (без баллов 0–10).

## 1. Выбор автора №2 — контраст, не «ещё один сильный»

Искать отличие **по нескольким осям сразу**, не похожего talking-head:

| ось | hadunkin (наблюдение корпуса) | искать у №2 |
|-----|-------------------------------|-------------|
| регистр | разговорный, часто мотивационный слоган | более аналитический, меньше «надо» |
| опора | почти всегда «я видел / поймал себя» | больше внешних фактов, ссылок, чужих моделей |
| место мысли | поле часто несёт тезис | меньше улицы, больше студии / аргумента |
| финал | часто предписание или хор | другой диапазон: разбор, вопрос, обрыв |
| эмоция | экспозиция страха, состояние, камера | иной диапазон, не копировать нишу |

SirDenisov в этот контур **не** класть: там шкала Vocal, другой вопрос.

Пока №2 не выбран — гипотезы ниже не «проверять на любом, кто под рукой».

## 2. Зафиксировать гипотезы *до* анализа №2

Чтобы не искать у второго то, что нашли у первого. Статус на старте: **подлежат опровержению**, не подтверждению.

| id | гипотеза | если у №2 то же | если у №2 иначе |
|----|----------|-----------------|-----------------|
| H1 | «Переворот чужой причины» — индивидуальный паттерн hadunkin | вероятно жанровое / общее | держать как индивидуальное, пока нет №3 |
| H2 | Личный опыт как основная опора — индивидуальная характеристика | жанр короткой речи | индивидуальное hadunkin |
| H3 | Сильный разговорный ролик необязательно заканчивается предписанием | общее устройство | предписание = норма жанра, обрыв = hadunkin |
| H4 | Повторяющийся слоган автора ≠ его способ мышления | общее правило корпуса | слоган = мышление (опровержение H4) |
| H5 | «Поле несёт мысль» — особенность hadunkin, не закон | если у №2 без поля мысль слабее — уточнить H5 | если студия несёт мысль так же — H5 не закон |

Не добавлять новые H «по ходу», пока не записаны в checkpoint. Иначе это уже подгонка.

## 3. Pipeline

```
инвентарь скриптом
  → Prompt 0 (классификация входа)
  → пилот 8–12 смешанных типов × P1–3 (калибровка стопов автора)
  → потоковый Prompt 1 (MODE=screening | deep)
  → кластер: после 3-го совпадения ОБЯЗАНА проверка гипотезы кластера (не автосклейка)
  → ранний P2/P3 на плотных, не ждать конца каталога
  → выборка P2/P3: типичные / плотные / контрпримеры
  → negative sampling + аудит SKIP
  → checkpoint (см. §8)
  → Devil's Advocate (не видел путь к гипотезе)
  → saturation check
  → Author Model v0.1
  → сравнение hadunkin × Author B
```

Не копить сотни Prompt 1 до механики. Плотный уникальный тезис сразу может получить P2/P3, пока корпус ещё идёт. Это исследование с обратной связью, не batch.

## 4. Prompt 0 — ничего не анализирует

Только вход и routing. Модель **сначала** ищет причины *не* идти в полный смысл.

Ответы:

- `entry_type`: мысль / история / наблюдение / процесс / диалог / мантра / реклама / полевой эпизод / смешанный
- `thesis_possible`: yes / no / unclear
- `enough_for_sense`: yes / no
- `decision`: FULL / LIMITED / SKIP
- `reason`: одна фраза
- `duplicate_of`: null | id
- `null` везде разрешён

FULL = различимый тезис правдоподобен, материала хватает.  
LIMITED = жест, настроение, процесс, мантра: усечённый смысл, без карты на 8 пунктов.  
SKIP = кредит STT, пустышка, реклама без речи, дубль текста.

**Ошибка шлюза.** На первых 2–3 авторах вручную смотреть **20–30% SKIP**. Считать false negative: дорогой тезис, который шлюз выкинул. Это важнее, чем false positive (лишний FULL).

Текст промпта: [`prompts_analysis_v2.md`](prompts_analysis_v2.md).

## 5. Prompt 1 — одна конституция, две глубины, схема с null

Не плодить два разных Prompt 1. Один schema-output:

`MODE=screening` | `MODE=deep`

Одинаковые поля и определения. Разная длина ответа.

**Сначала опровергнуть архитектуру, потом строить.**

Порядок в промпте:

1. Существует ли различимый тезис?
2. Альтернативы: только тема / сцена / настроение / призыв / повторяющаяся формула?
3. Если тезис нельзя уверенно отделить от темы — **не** реконструировать архитектуру. `thesis: null`.

Поля (везде допустим `null`):

```
topic
thesis
thesis_present          # true | false | null
thought_steps[]         # {text, function} | []
claims[]                # {claim, support_type, evidence, confidence}
opening_promise
conclusion
promise_resolved        # true | false | null
uncertainties[]
p2_allowed              # yes | no
p3_allowed              # yes | no
routing_reason
```

`support_type` как в v1: факт / исследование / наблюдение / личный опыт / … / ничем не подкреплено.

Каждый серьёзный вывод (тезис, переворот причины, «нет предписания»):

```
claim: …
evidence: цитата транскрипта
confidence: high | medium | low
class: OBSERVED | INFERRED
```

`thesis: null` — валидный результат, не ошибка заполнения.

`p2_allowed` / `p3_allowed` — routing в конце, с причиной. Пайплайн не сам «додумывает», что ролик лучший.

## 6. Три класса утверждений (сводка и Author Model)

Не смешивать в одной фразе «автор думает так».

| класс | что это | пример |
|-------|---------|--------|
| OBSERVED | прямо в тексте, с цитатой | в ролике N сначала «X», затем «Y» |
| INFERRED | наиболее вероятная интерпретация *этого* текста | вероятная модель Prompt 3 |
| CORPUS_PATTERN | повтор в **N независимых** роликах | переописание причины в k роликах |

CORPUS_PATTERN только после подсчёта и после попытки опровержения. Пилотная гипотеза ≠ CORPUS_PATTERN.

Prompt 3 по-прежнему: вероятная модель, не процесс создания. В сводке не переписывать INFERRED как биографию.

---

## 7. Выборки Prompt 2 и Prompt 3

Не только «лучшие». Иначе портрет лучшей версии автора, не автора.

Три корзины (квоты задавать на checkpoint, не заранее на весь корпус):

1. **Типичные** — характерные для текущего Author Model.  
2. **Плотные** — много собственного вывода.  
3. **Аномальные / контрпримеры** — сильнее всего противоречат текущей гипотезе.

Третья корзина обязательна. Вопрос не «где подтверждается», а «найди ролики, которые ломают модель».

P2 — если `p2_allowed` и был тезис.  
P3 — если `p3_allowed` и был свой вывод.  
Вариация кластера после *подтверждённой* склейки: не полный P2, строка входа в таблицу кластера.

## 8. Checkpoints и остановка по saturation

Не закон «40–80 смыслов». Бюджет — ориентир. Остановка — когда **новые ролики перестали менять Author Model**.

| точка | зачем |
|-------|--------|
| 8–12 (пилот) | калибровка стопов, Prompt 0, MODE |
| ~40 Prompt 1 | preliminary map: что повторяется, что казалось одним ядром, какие H, что опровергнет, **какие следующие ролики информативнее** |
| дальше | contradiction search, не добивание каталога |
| saturation | последние **10–15 новых FULL** не добавили категории тезисов, механик, контрпримеров — можно сводить модель |
| конец | Author Model v0.1 |

На каждом checkpoint:

- Что повторяется?
- Что считали повторением, а оказались разные мысли?
- Какие гипотезы живы?
- Что их опровергнет?
- Какие следующие ролики уменьшают неопределённость? (**active learning**)

Кластер: после **третьего** совпадения система **обязана проверить** гипотезу «это одно ядро». Не склеивать автоматически. Короткие однотипные — чаще да. Сложный ход — три похожие формулы ещё могут быть разными мыслями.

---

## 9. Negative sampling и калибровка промптов

Сохранять маленькую выборку **намеренно плохих / пограничных** роликов:

- без тезиса
- ложный тезис (шлюз или P1 чуть не выдумал)
- повтор слогана
- оборванная мысль
- чистый процесс
- реклама
- ошибочный SKIP Prompt 0

Это calibration set. Любое изменение промпта — прогон по нему: не начал ли метод снова находить философию там, где её нет.

## 10. Devil's Advocate

Отдельный прогон **без** истории построения гипотезы.

Дать только формулировку, например: «Автор регулярно строит мысль через разрушение очевидного объяснения».

Задача:

- максимально сильные контрпримеры;
- альтернативное объяснение паттерна (жанр, ниша, STT, отбор);
- какие данные сделали бы гипотезу ложной;
- что ошибочно приняли за индивидуальный стиль.

Выход — правки Author Model, не риторика «гипотеза жива».

---

## 11. Конечный артефакт: Author Model v0.1

Не «портрет». Живая гипотеза.

Разделы:

- Устойчиво наблюдаем (OBSERVED / CORPUS_PATTERN + N + evidence)
- Предполагаем (INFERRED)
- Противоречия
- Не знаем
- Вероятно жанровое
- Вероятно индивидуальное
- Нужен следующий автор для проверки

Fingerprint не психологическое заключение.

После Author B — таблица сравнения (§0). Пока её нет, Vocal не должен считать ходы hadunkin универсальными инструментами.

## 12. Что не делать

- Выбирать №2 «похож и сильный».
- Искать у №2 паттерны №1 до пререгистрации H1–H5.
- Два разных Prompt 1 (разъедутся определения).
- Останавливаться по числу файлов, игнорируя saturation.
- Автосклеивать кластер на третьем совпадении без проверки.
- Ставить баллы Vocal в этом контуре.
- Переносить генеративные принципы hadunkin как чеклист сценария №2.
- Пропускать аудит SKIP и negative set.
