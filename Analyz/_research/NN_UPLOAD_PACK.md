# Пакет для другой нейросети: корпус блогеров Vocal

Это самодостаточный вход. Задача — **способ мышления в короткой речи**, не оценка блогера, не баллы Vocal 0–10, не советы «как снять лучше», не психологический портрет.

Источник метода в репозитории: `Analyz/_research/` (протокол v2, промпты v2). Калибровка — корпус hadunkin. Контрастные авторы — пакеты в `Analyz/Done/`.

---

## 1. Как базу собирали (факт)

1. Выгрузка расшифровок по Instagram-id (один id = одна запись). Дубли транскрипции склеивали: брали более полный/поздний текст. Кредиты STT и пустышки короче ~8 слов не разбирали.
2. Калибровка на **одном** авторе (hadunkin): инвентарь → пилот 12 роликов × три слоя → Prompt 1 на роликах ~80+ слов (195 смыслов) → Prompt 2 только при реальном тезисе (52) → Prompt 3 только при своём выводе (40) → гипотезы по корпусу, не портрет.
3. Метод поправили (воронка, SKIP, кластеры, адвокат дьявола) и зафиксировали **Analysis Protocol v2**.
4. Следующие авторы брались **контрастом**, не «ещё один сильный»: другой регистр, опора, финал. Гипотезы H1–H5 с hadunkin замораживали *до* разбора, чтобы не подтверждать их на любом новом тексте.
5. На каждом новом корпусе: скриптовый инвентарь → Prompt 0 (FULL / LIMITED / SKIP) → пилот 8–12 смешанных типов → потоковый смысл → кластеры с проверкой после 3-го совпадения → выборка типичное / плотное / ломающее модель → глубина Prompt 1–3 → адвокат дьявола → переносимые операции для Vocal.

Уже разобранные корпуса (веб v2, часть с глубиной): chemistry_by_olga, marysstories, ira_podrez, alina_telling, doctor_belokon, doctor_komarovskiy, irina_hakamada, lermontova.career, labkovskiyofficial, ludmila.petranovskaya, natalia.remish (глубина не делалась). SirDenisov в этот контур **не** входит: там шкала Vocal.

Метрика качества: сколько утверждений о мышлении **выдержали попытку опровергнуть**, а не сколько роликов разобрано.

---

## 2. Как это планировалось в приложении

Корпус **не** подмешивается в биографию пользователя. Чужие истории, фразы и манеру копировать нельзя. Цитата блогера от первого лица не становится фактом автора.

Цепочка в продукте:

| слой | что из корпуса | куда в Vocal |
|---|---|---|
| сырьё | транскрипты, шлюз, смысл/механика/мышление | только исследование, не runtime |
| сжатие | `02_generative-principles.md`: когда применять, вход, ход, проверка, риск | кандидаты карточек |
| runtime I06 | версионируемый каталог карточек: id, пробел, режим мысли, механизм, стратегия вопроса, противопоказания, source reel IDs, attribution, duplicateGroup, evidenceStatus | библиотека ремесла |
| runtime V07 | селектор 0–4 карточек по **открытому пробелу** текущего `ThoughtState`; только формулировка `ask_question` | уже есть селектор; **production-каталог v07-1 пустой** (0 карточек). I06 не принят |

Иначе: исследование отвечает «какой ход мышления вообще бывает». Приложение в диалоге задаёт **один вопрос про пробел этой мысли**. Сценарий, `suggest_take` и портрет из корпуса не строятся. Нет корпуса — диалог обязан работать без приёмов.

## 3. Запреты аналитику

- Не ставить баллы, не хвалить, не советовать следующий дубль.
- Не выдумывать тезис, чтобы заполнить поля. Тема ≠ тезис. `null` и «нет в тексте» — нормальные ответы.
- Не путать слоган автора со способом мышления.
- Гость / диалог / чужая цитата не становятся паттерном автора без пометки.
- Prompt 2 только если в Prompt 1 был реальный тезис. Prompt 3 только если есть собственный вывод автора.
- Не копить сотни Prompt 1 до механики: плотный уникальный тезис можно сразу вести в P2/P3.

## 4. Пайплайн (делать по порядку)

```
инвентарь (id, слова, дубли)
  → Prompt 0  FULL | LIMITED | SKIP
  → пилот 8–12 разных типов × P1–P3
  → Prompt 1 screening на мыслящих
  → кластер (после 3 совпадений — гипотеза кластера, не автосклейка)
  → выборка typical / dense / counter
  → Prompt 1 deep + P2 + P3
  → negative sampling SKIP
  → Devil's Advocate (не видел путь к гипотезе)
  → Author Model v0.1
  → таблица: автор A | автор B | общее | различное | неизвестно
  → generative principles → кандидаты craft-карточек Vocal
```

## 5. Схемы JSON

### Prompt 0

```json
{
  "id": "string",
  "entry_type": "мысль|история|наблюдение|процесс|диалог|мантра|реклама|полевой эпизод|смешанный|мусор_STT",
  "thesis_possible": "yes|no|unclear",
  "enough_for_sense": "yes|no",
  "decision": "FULL|LIMITED|SKIP",
  "duplicate_of": null,
  "reason": "одно предложение"
}
```

### Prompt 1

```json
{
  "mode": "screening|deep",
  "topic": null,
  "thesis": null,
  "thesis_present": true,
  "thought_steps": [],
  "claims": [
    {
      "claim": "",
      "support_type": "факт|исследование|наблюдение|личный опыт|история другого человека|аналогия|причинно-следственное рассуждение|авторитет|общеизвестное предположение|ничем не подкреплено",
      "evidence": "цитата из транскрипта",
      "confidence": "high|medium|low",
      "class": "OBSERVED|INFERRED"
    }
  ],
  "opening_promise": null,
  "conclusion": null,
  "promise_resolved": null,
  "kernel_quotes": [],
  "uncertainties": [],
  "p2_allowed": "yes|no",
  "p3_allowed": "yes|no",
  "routing_reason": ""
}
```

Если тезис нельзя отделить от темы: `thesis: null`, `thesis_present: false`, остальное пустое, кроме `uncertainties` и routing.

### Prompt 2 (механика)

Только при `p2_allowed=yes`. Иначе `{ "full_p2": false, "cluster_id": "", "entry_difference": "" }`.

Поля: hook (механизм + почему продолжить), retention (список ходов), concreteness, rhetoric, density, voice, signature_hypothesis, chorus_vs_new (`chorus|new`).

### Prompt 3 (мышление)

Только при `p3_allowed=yes`. Иначе `{ "status": "не применялся", "reason": "" }`.

Поля: usual_X, author_sees_Y, generative_principle (когда / вход / ход / проверка / риск), `principle_wider_than_text`: yes|no.

### Карточка Vocal (цель сжатия, не сырой разбор)

```json
{
  "id": "craft_rename_case",
  "version": "research-0.1",
  "layer": "research",
  "applicableGapKey": "unnamed_category",
  "contentModes": ["explanation", "observation"],
  "mechanism": "наблюдаемый случай → рабочая категория → ограниченное следствие",
  "questionStrategy": "попросить назвать 2–3 категории, которые меняют решение, и какой признак их различит",
  "contraindications": ["нет наблюдаемого случая", "автор уже назвал категорию", "нужен фактчек, а не ярлык"],
  "sourceReelIds": ["DX7lcNSOG3e"],
  "speakerAttribution": "author",
  "duplicateGroup": null,
  "evidenceStatus": "hypothesis"
}
```

## 6. Пример одного ролика (готовый эталон)

Автор калибровки: hadunkin. Id: `DX7lcNSOG3e`. Слов: 100. Тип: мысль.

### Транскрипт

Я часто забываю самое главное, зачем я это вообще все делаю и с какими условиями. Я забываю, что я сказал себе просто когда-то, что я буду делать одно видео каждый день. Не важно, что я там скажу, не важно как. Я просто проверю себя, а смогу ли я. Посмотрю, что получилось. Но часто я вот эти вот все смыслы как-то сверху накидываю и забываю, что все на самом деле просто. Мы сами придумываем им правила, мы сами по ним действуем, мы сами в них играем, мы сами придумываем, что нам нужно что-то иное. А все на самом деле очень просто.

### Prompt 0

```json
{
  "id": "DX7lcNSOG3e",
  "entry_type": "мысль",
  "thesis_possible": "yes",
  "enough_for_sense": "yes",
  "decision": "FULL",
  "duplicate_of": null,
  "reason": "Есть различимый тезис про простой договор с собой и самодельные правила, текста хватает."
}
```

### Prompt 1 (сжатый эталон)

- Тема: зачем ежедневное.
- Тезис: исходный договор с собой простой; лишние смыслы — самодельные правила.
- Карта: забыл зачем → договор «одно видео в день, не важно что» → сверху смыслы → правила сами придумали.
- Опора: самонаблюдение, OBSERVED.
- Ядро: «я буду делать одно видео каждый день… Я просто проверю себя, а смогу ли я.»
- Неопределённость: не сказано, зачем тогда накидывает смыслы.
- p2_allowed: yes. p3_allowed: yes.

### Prompt 2

Hook: признание провала памяти («часто забываю самое главное, зачем»).  
Не ядро апатии: лекарство — вспомнить исходный договор, не «сними из пустоты».  
Signature (гипотеза): вернуть правило к минимальному чеку. chorus_vs_new: new (для этого автора в связке с соседними id про правила).

### Prompt 3 → принцип (уже сжатый для Vocal)

**Когда:** автор навалил условия на простое обещание себе.  
**Ход:** назвать стартовый чек → отделить наслоенные смыслы как самодельные правила → спросить, что останется, если вернуть минимальный договор.  
**Проверка:** в тексте есть исходный чек, не только жалоба.  
**Риск:** превратить в мотивационный слоган «просто начни».  
`principle_wider_than_text`: no, если остаёмся на договоре «одно видео в день».

Не копировать в вопрос пользователю фразы «мы сами в них играем». Спрашивать про *его* стартовый чек и *его* наслоение.

## 7. Что вернуть по новому автору

1. `corpus-summary.json` — объём, FULL/LIMITED/SKIP, ограничения (нет просмотров, нет картинки, неизвестна полнота выгрузки).
2. `00_prompt0-gateway.jsonl` — одна строка на id.
3. `01_corpus-hypotheses.md` — 5–8 гипотез: статус, цитаты, что корпус **не** доказывает.
4. `02_generative-principles.md` — только переносимые операции (когда / вход / ход / проверка / риск) и блок «Что не переносить».
5. `05_devil-advocate.md` — атака на главную гипотезу.
6. `craft-candidates.json` — 0–N карточек в схеме §5. Ноль карточек допустим. Не сочинять, если evidence слабый.

Сравнение с hadunkin обязательно: общее / различное / неизвестно. Общее — кандидат в Vocal. Различное — индивидуальный почерк, не карточка.
