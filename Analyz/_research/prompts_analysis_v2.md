# Промпты v2 (шлюз, схема, routing)

Калибровочные промпты v1 не удалять: [`prompts_analysis_bloggers.md`](../prompts_analysis_bloggers.md).  
Протокол: [`03_protocol-v2.md`](03_protocol-v2.md).

Запреты те же: не оценивать, не переписывать, не советовать, не ставить баллы. `null` и `нет в тексте` — валидные ответы.

`MODE=screening` и `MODE=deep` — одна схема, разная глубина. Не два промпта.

## Prompt 0 — классификация входа

Ты не анализируешь мысль и не реконструируешь архитектуру.

Задача: решить, **что перед нами** и **стоит ли** дорогой смысловой разбор.

ТРАНСКРИПТ: {{transcript}}
ID: {{id}}
СЛОВА: {{word_count}}
УЖЕ РАЗОБРАННЫЕ ДУБЛИ (если есть): {{duplicate_hints}}

Сначала ищи причины SKIP или LIMITED. Полный разбор — только если их нет.

Тип (`entry_type`), ровно один; если не уверен — `смешанный` + пояснение в `reason`:
мысль / история / наблюдение / процесс / диалог / мантра / реклама / полевой эпизод / смешанный / мусор_STT

`thesis_possible`: yes | no | unclear  
Есть ли *потенциальный* тезис (утверждение, которое зритель должен начать считать), а не только тема, жест, настроение, призыв, формула?

`enough_for_sense`: yes | no

`decision`:
- FULL — тезис правдоподобен, текста хватает на смысл
- LIMITED — жест / процесс / мантра / диалог без единой архитектуры: усечённый смысл позже, не 8 разделов
- SKIP — пустышка, кредит STT, реклама без речи, дубль текста

`duplicate_of`: id или null

`reason`: одно предложение, почему такое решение.

Не формулируй центральную мысль. Не строй карту шагов. Не выдумывай тезис, чтобы заполнить поле.

Верни JSON:

```
{
  "entry_type": "",
  "thesis_possible": "yes|no|unclear",
  "enough_for_sense": "yes|no",
  "decision": "FULL|LIMITED|SKIP",
  "duplicate_of": null,
  "reason": ""
}
```

## Prompt 1 — смысл (v2)

Роль и запреты как в v1. Конституция полей одна.

MODE: {{screening|deep}}

ТРАНСКРИПТ: {{transcript}}
PROMPT_0: {{prompt0_json}}
КОНТЕКСТ (опционально, не для оценки): {{author}} {{niche}}

### Порядок (обязателен)

1. Существует ли в тексте различимый тезис?
2. Найди альтернативу: возможно, перед тобой только тема, сцена, настроение, призыв или повторяющаяся формула.
3. Если тезис нельзя уверенно отделить от темы — не реконструируй архитектуру. `thesis: null`, `thesis_present: false`. Остальные поля — null или пустые списки, кроме `uncertainties` и routing.
4. Только если тезис отделён — заполняй шаги, утверждения, начало/конец, ядро.

В MODE=screening: коротко (поля заполнены, без эссе).  
В MODE=deep: те же поля, развёрнутые `thought_steps` и `claims` как в v1 (карта, опора, траектория, ядро 3–5 цитат автора).

### Схема (везде допустим null)

```
{
  "mode": "screening|deep",
  "topic": null,
  "thesis": null,
  "thesis_present": null,
  "thought_steps": [],
  "claims": [
    {
      "claim": "",
      "support_type": "",
      "evidence": "",
      "confidence": "high|medium|low",
      "class": "OBSERVED|INFERRED"
    }
  ],
  "opening_promise": null,
  "conclusion": null,
  "promise_resolved": null,
  "kernel_quotes": [],
  "uncertainties": [],
  "p2_allowed": "yes|no",
  "p3_allowed": "yes|no",
  "routing_reason": ""
}
```

`support_type`: факт | исследование | наблюдение | личный опыт | история другого человека | аналогия | причинно-следственное рассуждение | авторитет | общеизвестное предположение | ничем не подкреплено

Серьёзный вывод без `evidence` (цитата транскрипта) и `confidence` — не принимать.

`p2_allowed`: yes только если был реальный тезис.  
`p3_allowed`: yes только если есть собственный вывод автора, не только сцена, мантра, процесс или повтор известного слогана.

Ядро (`kernel_quotes`) — формулировки автора, не пересказ.

## Prompt 2 и Prompt 3 — дельты к v1

Текст разделов v1 сохраняется. Добавки:

**Оба:** на вход — схема Prompt 1, не обязательно полный транскрипт (кроме спорных цитат). Каждый сильный вывод: claim + evidence + confidence + class.

**Prompt 2:** поле `chorus_vs_new` — хор корпуса (уже звучавшая формула) vs новый ход. Если после проверки это вариация подтверждённого кластера — не полный разбор: `{ "cluster_id": "", "entry_difference": "", "full_p2": false }`.

**Prompt 3:** если `p3_allowed=no` — `{ "status": "не применялся", "reason": "" }`, без генеративного принципа. Рядом с принципом: `principle_wider_than_text`: yes|no. Цепочка: пропуски как `null`, не заполнять. Класс всех выводов INFERRED, пока не стали CORPUS_PATTERN в Author Model.

Выборки: типичные / плотные / контрпримеры — задаёт протокол, не «возьми лучшие».
